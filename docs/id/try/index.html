Demo interaktif

Coba Pain001 di Browser Anda

Masukkan file CSV, gunakan contoh, atau tempel data Anda sendiri — validasi berjalan seketika, sepenuhnya di browser Anda, dan tidak ada data yang keluar dari perangkat Anda.

Cara validator ini membantu Anda

  • ✓Uji data pembayaran terhadap pemeriksaan yang diterapkan bank — kolom wajib, checksum IBAN, struktur BIC, total kontrol
  • ✓Hasilkan file transfer kredit pain.001.001.09 yang berfungsi dan dapat Anda periksa, salin, atau unduh
  • ✓Buktikan hasilnya terhadap skema ISO 20022 resmi — XSD asli, divalidasi di browser Anda

Informasi penting

  • Tidak ada yang diunggah. File Anda dibaca oleh browser Anda sendiri dan tidak pernah keluar dari perangkat Anda — tidak ada server, tidak ada penyimpanan, tidak ada telemetri. Aman untuk data asli, meskipun data uji yang disamarkan selalu merupakan praktik yang baik.
  • Hanya alat pengujian. File tidak pernah dikirim untuk diproses dan tidak ada pembayaran yang dapat terjadi dari apa pun yang Anda lakukan di sini.
  • Kolom yang diharapkan: payment_id, payment_amount, currency, nama debitur dan kreditur / IBAN / BIC, requested_execution_date — pemisah koma, titik koma, dan tab terdeteksi secara otomatis. Unduh contoh di bawah untuk digunakan sebagai templat ekspor Anda sendiri.
  • Tanpa biaya. Alat ini, dan toolchain lengkap di baliknya, gratis dan bersumber terbuka.

Verifikasi sendiri

"Tidak ada yang diunggah" adalah klaim yang dapat Anda uji sendiri dalam dua menit:

  1. Buka DevTools → Network, lalu gunakan demo ini. Satu-satunya permintaan adalah GET same-origin untuk aset halaman ini, mesin WASM, dan skema — tidak ada satu pun yang membawa data Anda.
  2. Jalankan gerbang XSD sekali, lalu alihkan DevTools ke Offline (atau matikan Wi-Fi). Seluruh demo — termasuk gerbang skema resmi — tetap berfungsi: service worker menyimpan semuanya dalam cache setelah penggunaan pertama.
  3. Halaman ini juga bersumber terbuka — logika demo adalah satu modul tanpa dependensi yang dapat Anda baca seluruhnya.

Tidak ada skrip analitik, tidak ada layanan pelaporan kesalahan, tidak ada font pihak ketiga, dan tidak ada endpoint laporan CSP — pelaporan itu sendiri akan menjadi koneksi keluar.

3

Buktikan terhadap XSD ISO 20022 resmi

Langkah 1–2 menjalankan pemeriksaan cepat yang ditulis manual. Langkah ini menjalankan yang sesungguhnya: runtime Python (melalui WebAssembly) yang mengeksekusi xmlschema terhadap skema pain.001.001.09 resmi — kelas validasi yang sama dengan yang dilakukan CLI. Mesin berukuran ~13 MB disajikan dari situs ini dan diunduh sekali, saat Anda memintanya (mesin mulai diunduh secara diam-diam segera setelah langkah 2 menghasilkan XML yang valid).

Hasilkan XML pada langkah 2 terlebih dahulu — gerbang XSD memvalidasi keluaran tersebut.

    Semua yang ada di halaman ini berjalan di browser Anda — tidak ada yang diunggah, disimpan, atau dikirim ke mana pun. Demo ini mengimplementasikan sebagian dari pipeline (kolom wajib, IBAN mod-97, struktur BIC, format jumlah dan tanggal, total kontrol NbOfTxs/CtrlSum yang dihitung ulang). Langkah 3 menjalankan gerbang XSD resmi langsung di sini melalui WebAssembly. Toolchain yang terinstal menambahkan validasi JSON Schema dan lima buku aturan skema di atasnya — instal CLI untuk pipeline lengkap.

    Apa yang ditunjukkan demo ini — dan apa yang ditambahkan pipeline sebenarnya

    Setiap batch contoh juga dapat diunduh sebagai file CSV untuk digunakan sebagai templat ekspor ERP atau spreadsheet Anda sendiri — baris header adalah kontraknya.

    Demo di atas mengimplementasikan lapisan fail-fast dari pipeline Pain001: pemeriksaan kolom wajib, checksum IBAN mod-97 ISO 13616, struktur BIC ISO 9362, format jumlah dan tanggal, serta total kontrol (NbOfTxs, CtrlSum) yang dihitung ulang dari data alih-alih dipercaya begitu saja. Coba menu "Sisipkan kesalahan…" — setiap skenario menanamkan tepat satu cacat realistis (digit IBAN yang tertukar, BIC yang salah bentuk, kolom yang hilang, jumlah dengan desimal koma gaya Eropa, tanggal yang mustahil) dan menunjukkan temuan tingkat baris yang jika tidak, baru akan dilaporkan gateway bank beberapa hari kemudian.

    Toolchain yang terinstal menjalankan gerbang yang jauh lebih dalam: validasi JSON Schema per rekaman dengan normalisasi alias kolom, lima buku aturan skema (SEPA SCT, Instant, SDD Core, B2B, lintas negara) dengan keluaran --explain aturan demi aturan, dan validasi akhir dokumen yang dirender terhadap XSD ISO 20022 resmi sebelum satu byte pun ditulis. Sepuluh versi pain.001 dan pain.008.001.02 didukung.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Langkah 3 di atas bukan simulasi: langkah ini menjalankan runtime Python di WebAssembly dan mengeksekusi xmlschema terhadap skema pain.001.001.09 resmi, yang disajikan dari situs ini — kelas gerbang XSD yang sama dengan yang diterapkan CLI. Yang tetap hanya tersedia di CLI adalah sisa pipeline: normalisasi JSON Schema, lima buku aturan skema dengan --explain, dan sepuluh definisi pesan lainnya.
