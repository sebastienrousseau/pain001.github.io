อภิธานศัพท์

อภิธานศัพท์การชำระเงิน ISO 20022 ฉบับเข้าใจง่าย

ศัพท์การชำระเงินในภาษาที่เข้าใจง่าย — สำหรับผู้ที่ลงนามอนุมัติไฟล์ ไม่ใช่เพียงผู้ที่สร้างไฟล์

3 นาทีในการอ่าน ตรวจสอบล่าสุด 2026-07-26

สารบัญ

  1. ข้อความ
  2. สกีมและกฎเกณฑ์
  3. รหัสระบุตัวตนและข้อมูล
  4. ศัพท์เกี่ยวกับเครื่องมือที่ใช้ในเว็บไซต์นี้

คำนิยามอย่างเข้าใจง่ายของศัพท์ที่ปรากฏทั่วเว็บไซต์นี้และในเอกสารช่องทางบริการของธนาคารคุณ เขียนขึ้นเพื่อผู้บริหารการเงินและทีมปฏิบัติการเป็นอันดับแรก และเพื่อวิศวกรเป็นอันดับรอง

ข้อความ#

pain.001 — Customer Credit Transfer Initiation ข้อความ XML ที่ลูกค้าส่งให้ธนาคารเพื่อสั่งโอนเงินหนึ่งรายการขึ้นไป ตระกูล "pain" หมายถึงการเริ่มต้นคำสั่งชำระเงิน ส่วน .001 คือหมายเลขข้อความ และเลขเวอร์ชันท้ายสุด (.001.09) เป็นตัวกำหนดสกีมา

pain.002 — Customer Payment Status Report คำตอบของธนาคารต่อ pain.001 หรือ pain.008 ของคุณ ว่าตอบรับ ตอบรับบางส่วน หรือปฏิเสธ พร้อมรหัสเหตุผลตามมาตรฐาน ISO รายธุรกรรม

pain.008 — Customer Direct Debit Initiation คู่แฝดฝั่งเรียกเก็บเงินของ pain.001 คุณเป็นฝ่ายเรียกเก็บเงินที่ค้างชำระภายใต้หนังสือยินยอม แทนที่จะเป็นฝ่ายจ่ายเงินออก

pacs.008 / pacs.009 ข้อความชำระดุลระหว่างธนาคารที่คำสั่งของคุณจะถูกแปลงไปเมื่อธนาคารตอบรับแล้ว องค์กรธุรกิจไม่เคยเป็นผู้สร้างข้อความเหล่านี้ ธนาคารเป็นผู้แลกเปลี่ยนกันเอง

camt.052 / camt.053 / camt.054 รายงานบัญชี ได้แก่ รายงานระหว่างวัน รายการเดินบัญชีสิ้นวัน และการแจ้งเตือนรายการเดบิต/เครดิต ตามลำดับ โดย camt.053 คือไฟล์ที่ทีมกระทบยอดใช้งานทุกเช้า

MT101 ข้อความตัวอักษรแบบเดิมของ SWIFT ที่ใช้ "ขอให้โอนเงิน" ซึ่ง pain.001 เข้ามาแทนที่ การส่งต่อ MT101 ระหว่างธนาคารจะยุติในวันที่ 14 พฤศจิกายน 2026 โดยเปลี่ยนไปใช้ pain.001.001.09 แทน ส่วน MT101 แบบองค์กรถึงธนาคารจะคงอยู่ต่อไปตามดุลยพินิจของแต่ละธนาคารเท่านั้น

สกีมและกฎเกณฑ์#

SEPA SCT / SCT Inst สกีมการโอนเงินสกุลยูโร (แบบมาตรฐานและแบบทันที) ซึ่งกำกับด้วยกฎเกณฑ์ของ European Payments Council การโอนแบบทันทีจะเสร็จสิ้นภายในไม่กี่วินาที ตลอด 24 ชั่วโมง

SEPA SDD Core / B2B สกีมการหักบัญชีอัตโนมัติสกุลยูโร — Core สำหรับผู้บริโภค (มีสิทธิ์ขอคืนเงิน) และ B2B สำหรับธุรกิจ (ไม่มีสิทธิ์ขอคืนเงิน และตรวจสอบหนังสือยินยอมเข้มงวดกว่า)

CBPR+ Cross-Border Payments and Reporting Plus คือแนวปฏิบัติการใช้งานที่กำหนดรูปแบบข้อความ ISO 20022 สำหรับธนาคารตัวแทนในเครือข่าย SWIFT เมื่อผู้คนพูดถึง "การย้ายไปใช้ ISO 20022 ของ SWIFT" พวกเขาหมายถึง CBPR+ นั่นเอง

HVPS+ การกำหนดรูปแบบในลักษณะเดียวกันสำหรับระบบการชำระเงินมูลค่าสูง (T2, CHAPS, Fedwire และระบบอื่นในกลุ่มเดียวกัน)

CGI-MP Common Global Implementation — Market Practice คือกลุ่มที่ทำให้วิธีที่องค์กรธุรกิจใช้ข้อความ pain กับธนาคารต่าง ๆ สอดคล้องกัน เพื่อให้ไฟล์รูปแบบเดียวใช้ได้กับธนาคารคู่ค้าหลายราย

Verification of Payee (VoP) การตรวจความตรงกันของชื่อกับ IBAN ที่สหภาพยุโรปกำหนดให้ใช้กับการโอนเงิน SEPA ทุกรายการตั้งแต่วันที่ 9 ตุลาคม 2025 ดำเนินการโดยผู้ให้บริการชำระเงินในขณะประมวลผล ความถูกต้องของข้อมูลผู้รับเงินจึงเป็นตัวชี้ว่าผลการตรวจจะตรงกันหรือไม่

รหัสระบุตัวตนและข้อมูล#

IBAN International Bank Account Number (ISO 13616) เลขที่บัญชีธนาคารสากลซึ่งตรวจสอบตัวเองได้ด้วย checksum แบบ mod-97 — จึงตรวจพบการสลับตำแหน่งตัวเลขเพียงหลักเดียวได้ตั้งแต่ก่อนส่งไฟล์

BIC / BICFI รหัสระบุสถาบันการเงินตามมาตรฐาน ISO 9362 องค์ประกอบ XML คือ <BIC> ใน pain.001.001.03 แต่เปลี่ยนเป็น <BICFI> ตั้งแต่เวอร์ชัน 9 — การเปลี่ยนชื่อนี้ทำให้ไฟล์ถูกปฏิเสธจริงในระหว่างการอัปเกรดเวอร์ชัน

LEI Legal Entity Identifier (ISO 17442) — รหัสระบุนิติบุคคลระดับสากลความยาว 20 อักขระ ปัจจุบันมีที่ใช้งานอยู่กว่า 3 ล้านรหัส และหน่วยงานกำกับดูแลกำหนดให้ใช้ในการชำระเงินมากขึ้นเรื่อย ๆ

UETR Unique End-to-end Transaction Reference — รหัส UUID ที่ทำให้ติดตามรายการชำระเงินได้ตลอดสายธนาคารตัวแทน (SWIFT gpi)

ที่อยู่แบบมีโครงสร้าง / แบบผสม ที่อยู่ทางไปรษณีย์ที่แยกเป็นองค์ประกอบ XML แต่ละส่วน (ถนน เมือง รหัสไปรษณีย์ ประเทศ) เทียบกับที่อยู่แบบบรรทัดข้อความอิสระ ตั้งแต่วันที่ 14 พฤศจิกายน 2026 CBPR+ จะปฏิเสธที่อยู่ที่ไม่มีโครงสร้างเลย ส่วนแบบผสม — ระบุเมืองและประเทศแบบมีโครงสร้าง พร้อมบรรทัดที่อยู่ได้ไม่เกินสองบรรทัด บรรทัดละ 70 อักขระ — ยังคงใช้ได้

NbOfTxs / CtrlSum ยอดควบคุมในส่วนหัวของกลุ่มรายการ ได้แก่ จำนวนธุรกรรมและผลรวมจำนวนเงิน ธนาคารจะคำนวณค่าเหล่านี้ใหม่ หากค่าของคุณไม่ตรงกัน ไฟล์จะถูกตีกลับ Pain001 คำนวณค่าเหล่านี้จากระเบียนที่ผ่านการตรวจสอบเสมอ

ผู้รับภาระค่าธรรมเนียม ผู้ที่จ่ายค่าธรรมเนียม ได้แก่ DEBT (ผู้ส่งเงิน), CRED (ผู้รับเงิน), SHAR (แบ่งกันจ่าย), SLEV (ตามกฎของสกีม) โดยรหัสเดิมของ MT คือ OUR/BEN/SHA จะเทียบได้กับสามรหัสแรก

ข้อมูลการชำระเงิน ฟิลด์ที่ระบุว่า "เงินก้อนนี้จ่ายเพื่ออะไร" — เป็นข้อความอิสระ (140 อักขระ) หรือรายการอ้างอิงแบบมีโครงสร้าง เป็นฟิลด์ที่ทีมกระทบยอดอยากให้ทุกคนกรอกให้ถูกต้องครบถ้วน

ศัพท์เกี่ยวกับเครื่องมือที่ใช้ในเว็บไซต์นี้#

การตรวจสอบด้วย XSD การตรวจไฟล์ XML กับนิยามสกีมา ISO 20022 อย่างเป็นทางการ Pain001 ถือว่านี่คือเกณฑ์บังคับก่อนที่จะเขียนไฟล์ใด ๆ

MCP — Model Context Protocol มาตรฐานเปิดที่ผู้ช่วย AI ใช้เรียกเครื่องมือภายนอก pain001-mcp เปิดให้ไคลเอนต์ MCP ใดก็ตามเรียกใช้เครื่องมือด้านการชำระเงิน 17 รายการ ภายในเครื่องผ่าน stdio

LSP — Language Server Protocol มาตรฐานการผสานกับโปรแกรมแก้ไขโค้ดที่อยู่เบื้องหลังการแจ้งข้อผิดพลาดใน IDE pain001-lsp ใช้มาตรฐานนี้ตรวจสอบไฟล์ชำระเงินขณะที่คุณพิมพ์

SBOM Software Bill of Materials — บัญชีรายการที่เครื่องอ่านได้ของทุกส่วนประกอบที่ซอฟต์แวร์พึ่งพาในแต่ละรุ่นที่เผยแพร่ สร้างในรูปแบบ CycloneDX สำหรับการเผยแพร่ส่วนหลักของ Pain001

มีคำใดตกหล่นหรือไม่ เสนอคำศัพท์ได้ที่นี่ — อภิธานศัพท์นี้เติบโตไปตามคำถามที่ผู้คนถามกันจริง
