เดโมแบบอินเทอร์แอกทีฟ

ทดลองใช้ Pain001 ในเบราว์เซอร์ของคุณ

ลากไฟล์ CSV มาวาง ใช้ตัวอย่าง หรือวางระเบียนของคุณเอง — การตรวจสอบทำงานทันที ทั้งหมดในเบราว์เซอร์ของคุณ และไม่มีข้อมูลใดออกจากเครื่องของคุณ

เครื่องมือตรวจสอบนี้ช่วยคุณอย่างไร

  • ✓ทดสอบข้อมูลการชำระเงินกับการตรวจสอบที่ธนาคารใช้ — ฟิลด์ที่จำเป็น เช็กซัม IBAN โครงสร้าง BIC ยอดรวมควบคุม
  • ✓สร้างไฟล์ pain.001.001.09 โอนเครดิตที่ใช้งานได้จริง ซึ่งคุณสามารถตรวจดู คัดลอก หรือดาวน์โหลดได้
  • ✓พิสูจน์ผลลัพธ์กับสคีมา ISO 20022 ทางการ — XSD ของแท้ ตรวจสอบในเบราว์เซอร์ของคุณ

ข้อมูลสำคัญ

  • ไม่มีการอัปโหลดใด ๆ ไฟล์ของคุณถูกอ่านโดยเบราว์เซอร์ของคุณเองและไม่เคยออกจากเครื่องของคุณ — ไม่มีเซิร์ฟเวอร์ ไม่มีการจัดเก็บ ไม่มีเทเลเมทรี ปลอดภัยสำหรับข้อมูลจริง แม้ว่าการใช้ข้อมูลทดสอบที่ปกปิดแล้วจะเป็นแนวปฏิบัติที่ดีเสมอ
  • เป็นเครื่องมือทดสอบเท่านั้น ไฟล์จะไม่ถูกส่งไปประมวลผล และไม่มีการชำระเงินใดเกิดขึ้นได้จากสิ่งที่คุณทำที่นี่
  • คอลัมน์ที่คาดหวัง: payment_id, payment_amount, currency, ชื่อผู้ชำระเงินและผู้รับเงิน / IBAN / BIC, requested_execution_date — ตัวคั่นแบบจุลภาค อัฒภาค และแท็บจะถูกตรวจพบโดยอัตโนมัติ ดาวน์โหลดตัวอย่างด้านล่างเพื่อใช้เป็นแม่แบบสำหรับการส่งออกของคุณเอง
  • ไม่มีค่าใช้จ่าย เครื่องมือนี้และชุดเครื่องมือเต็มรูปแบบที่อยู่เบื้องหลังเป็นซอฟต์แวร์ฟรีและโอเพนซอร์ส

ตรวจสอบด้วยตัวคุณเอง

"ไม่มีการอัปโหลดใด ๆ" คือคำกล่าวอ้างที่คุณพิสูจน์ได้เองภายในสองนาที:

  1. เปิด DevTools → Network แล้วใช้งานเดโม คำขอที่มีอยู่มีเพียง GET แบบ same-origin สำหรับทรัพยากรของหน้านี้ เอนจิน WASM และสคีมา — ไม่มีคำขอใดนำข้อมูลของคุณไปด้วย
  2. รันเกต XSD หนึ่งครั้ง จากนั้นสลับ DevTools เป็น Offline (หรือปิด Wi-Fi) เดโมทั้งหมด — รวมถึงเกตสคีมาทางการ — ยังคงทำงานได้: service worker จะแคชทุกอย่างหลังการใช้งานครั้งแรก
  3. หน้านี้ก็เป็นโอเพนซอร์สเช่นกัน — ตรรกะของเดโมเป็นโมดูลเดียวที่ไม่มีดีเพนเดนซี ซึ่งคุณอ่านได้ทั้งหมด

ไม่มีสคริปต์วิเคราะห์ ไม่มีบริการรายงานข้อผิดพลาด ไม่มีฟอนต์จากบุคคลที่สาม และไม่มีปลายทางรายงาน CSP — เพราะการรายงานเองก็เป็นการเชื่อมต่อขาออกอย่างหนึ่ง

ดาวน์โหลดตัวอย่างเพื่อใช้เป็นแม่แบบของคุณเอง: โอนเครดิต SEPA · ข้ามพรมแดน · ชุด 20 แถว

3

พิสูจน์กับ XSD ทางการของ ISO 20022

ขั้นตอนที่ 1–2 รันการตรวจสอบที่เขียนด้วยมือและรวดเร็ว ขั้นตอนนี้รันของจริง: รันไทม์ Python (ผ่าน WebAssembly) ทำงาน xmlschema กับสคีมา pain.001.001.09 ทางการ — การตรวจสอบระดับเดียวกับที่ CLI ทำ เอนจินขนาด ~13 MB ให้บริการจาก เว็บไซต์นี้และดาวน์โหลดเพียงครั้งเดียวเมื่อคุณร้องขอ (จะเริ่มดาวน์โหลดอย่างเงียบ ๆ ทันทีที่ ขั้นตอนที่ 2 สร้าง XML ที่ถูกต้อง)

สร้าง XML ในขั้นตอนที่ 2 ก่อน — เกต XSD จะตรวจสอบเอาต์พุตนั้น

    ทุกอย่างบนหน้านี้ทำงานในเบราว์เซอร์ของคุณ — ไม่มีการอัปโหลด จัดเก็บ หรือส่งไปที่ใด เดโมนี้ครอบคลุมส่วนย่อยของไปป์ไลน์ (ฟิลด์ที่จำเป็น, IBAN mod-97, โครงสร้าง BIC, รูปแบบจำนวนเงิน และวันที่, ยอดรวมควบคุม NbOfTxs/CtrlSum ที่คำนวณใหม่) ขั้นตอนที่ 3 รันเกต XSD ทางการที่นี่ผ่าน WebAssembly ชุดเครื่องมือที่ติดตั้ง เพิ่มการตรวจสอบ JSON Schema และชุดกฎห้าสคีมไว้ด้านบน — ติดตั้ง CLI เพื่อไปป์ไลน์ที่สมบูรณ์

    เดโมนี้แสดงอะไร — และไปป์ไลน์จริงเพิ่มอะไร

    ชุดตัวอย่างแต่ละชุดยังดาวน์โหลดเป็นไฟล์ CSV ได้ เพื่อใช้เป็นแม่แบบสำหรับการส่งออกจาก ERP หรือสเปรดชีตของคุณเอง — แถวส่วนหัวคือข้อตกลง

    เดโมด้านบนครอบคลุมเลเยอร์ fail-fast ของไปป์ไลน์ Pain001: การตรวจสอบฟิลด์ที่จำเป็น, เช็กซัม IBAN mod-97 ตาม ISO 13616, โครงสร้าง BIC ตาม ISO 9362, รูปแบบจำนวนเงินและวันที่ และยอดรวมควบคุม (NbOfTxs, CtrlSum) ที่คำนวณใหม่จากระเบียนแทนที่จะเชื่อตามที่ให้มา ลองเมนู "แทรกข้อผิดพลาด…" — แต่ละสถานการณ์จะวางข้อบกพร่องสมจริงไว้หนึ่งจุดพอดี (ตัวเลข IBAN สลับ, BIC ผิดรูปแบบ, คอลัมน์หาย, จำนวนเงินทศนิยมแบบจุลภาคยุโรป, วันที่ที่เป็นไปไม่ได้) และแสดงผลการตรวจระดับแถวที่เกตเวย์ของธนาคารจะรายงานในอีกหลายวันให้หลัง

    ชุดเครื่องมือที่ติดตั้งรันเกตที่ลึกกว่ามาก: การตรวจสอบ JSON Schema ต่อระเบียนพร้อมการปรับชื่อฟิลด์ให้เป็นมาตรฐาน, ชุดกฎห้าสคีม (SEPA SCT, Instant, SDD Core, B2B, ข้ามพรมแดน) พร้อมเอาต์พุต --explain ทีละกฎ และการตรวจสอบขั้นสุดท้ายของเอกสารที่สร้างขึ้นกับ XSD ทางการของ ISO 20022 ก่อนเขียนข้อมูลแม้แต่ไบต์เดียว รองรับสิบเวอร์ชันของ pain.001 และ pain.008.001.02 ด้วย

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    ขั้นตอนที่ 3 ด้านบนไม่ใช่การจำลอง: มันบูตรันไทม์ Python ใน WebAssembly และรัน xmlschema กับสคีมา pain.001.001.09 ทางการซึ่งให้บริการจากเว็บไซต์นี้ — เกต XSD ระดับเดียวกับที่ CLI ใช้ ส่วนที่ยังคงมีเฉพาะใน CLI คือไปป์ไลน์ที่เหลือ: การปรับให้เป็นมาตรฐานด้วย JSON Schema, ชุดกฎห้าสคีมพร้อม --explain และนิยามข้อความอีกสิบรายการ
