브라우저에서 Pain001 사용해 보기

CSV를 끌어다 놓거나, 샘플을 사용하거나, 직접 레코드를 붙여넣으세요 — 검증은 즉시, 전적으로 브라우저 안에서 실행되며 어떤 데이터도 사용자의 기기를 벗어나지 않습니다.

이 검증 도구가 도움이 되는 방식

  • ✓은행이 적용하는 검사로 결제 데이터를 테스트합니다 — 필수 필드, IBAN 체크섬, BIC 구조, 컨트롤 합계
  • ✓확인, 복사, 다운로드할 수 있는 실제로 동작하는 pain.001.001.09 신용이체 파일을 생성합니다
  • ✓공식 ISO 20022 스키마로 결과를 증명합니다 — 진본 XSD를 브라우저에서 직접 검증합니다

중요 안내

  • 아무것도 업로드되지 않습니다. 파일은 사용자의 브라우저가 직접 읽으며 기기를 벗어나는 일이 없습니다 — 서버도, 저장도, 텔레메트리도 없습니다. 실제 데이터에도 안전하지만, 마스킹된 테스트 데이터를 사용하는 것이 항상 바람직합니다.
  • 테스트 전용 도구입니다. 파일이 처리 목적으로 제출되는 일은 없으며, 여기서 어떤 작업을 하더라도 실제 지급이 발생하지 않습니다.
  • 예상 열: payment_id, payment_amount, currency, 채무자 및 채권자 이름 / IBAN / BIC, requested_execution_date — 쉼표, 세미콜론, 탭 구분자는 자동으로 감지됩니다. 아래에서 샘플을 다운로드하여 자체 내보내기용 템플릿으로 사용하세요.
  • 요금이 없습니다. 이 도구와 그 기반이 되는 전체 툴체인은 무료 오픈 소스입니다.

직접 확인해 보세요

"아무것도 업로드되지 않습니다"라는 주장은 2분이면 직접 검증할 수 있습니다:

  1. DevTools → Network를 연 다음 데모를 사용해 보세요. 발생하는 요청은 이 페이지의 자산, WASM 엔진, 스키마를 가져오는 same-origin GET뿐이며, 사용자의 데이터를 전송하는 요청은 하나도 없습니다.
  2. XSD 게이트를 한 번 실행한 뒤 DevTools를 Offline으로 전환하세요(또는 Wi-Fi를 끄세요). 공식 스키마 게이트를 포함한 데모 전체가 계속 작동합니다: 서비스 워커가 최초 사용 후 모든 것을 캐시하기 때문입니다.
  3. 이 페이지 역시 오픈 소스입니다 — 데모 로직은 의존성이 없는 단일 모듈로, 전체를 직접 읽어 보실 수 있습니다.

분석 스크립트도, 오류 보고 서비스도, 서드파티 폰트도, CSP 보고 엔드포인트도 없습니다 — 보고 자체가 외부로 나가는 연결이 되기 때문입니다.

공식 ISO 20022 XSD로 증명하기

1–2단계는 빠른 수작업 검사를 실행합니다. 이 단계는 진짜를 실행합니다: Python 런타임(WebAssembly 기반)이 xmlschema 을(를) 공식 pain.001.001.09 스키마에 대해 실행합니다 — CLI가 수행하는 것과 같은 등급의 검증입니다. 약 13 MB 크기의 엔진은 이 사이트에서 제공되며, 요청 시 한 번만 다운로드됩니다(2단계에서 유효한 XML이 생성되는 즉시 조용히 다운로드가 시작됩니다).

먼저 2단계에서 XML을 생성하세요 — XSD 게이트는 해당 출력을 검증합니다.

    이 페이지의 모든 것은 브라우저에서 실행됩니다 — 아무것도 업로드, 저장, 전송되지 않습니다. 이 데모는 파이프라인의 일부(필수 필드, IBAN mod-97, BIC 구조, 금액 및 날짜 형식, 재계산된 NbOfTxs/CtrlSum 컨트롤 합계)를 구현합니다. 3단계는 WebAssembly를 통해 공식 XSD 게이트를 바로 여기서 실행합니다. 설치된 툴체인은 그 위에 JSON Schema 검증과 다섯 가지 스킴 룰북을 추가합니다 — 전체 파이프라인을 사용하려면 CLI를 설치하세요.

    이 데모가 보여 주는 것 — 그리고 실제 파이프라인이 더하는 것

    각 샘플 배치는 CSV 파일로도 다운로드하여 자체 ERP 또는 스프레드시트 내보내기의 템플릿으로 사용할 수 있습니다 — 헤더 행이 곧 계약입니다.

    위 데모는 Pain001 파이프라인의 fail-fast 계층을 구현합니다: 필수 필드 검사, ISO 13616 mod-97 IBAN 체크섬, ISO 9362 BIC 구조, 금액 및 날짜 형식, 그리고 레코드로부터 재계산되는(그대로 신뢰하지 않는) 컨트롤 합계 (NbOfTxs, CtrlSum) 입니다. "오류 삽입…" 메뉴를 사용해 보세요 — 각 시나리오는 현실적인 결함을 정확히 하나씩(뒤바뀐 IBAN 숫자, 잘못된 형식의 BIC, 누락된 열, 유럽식 쉼표 소수점 금액, 불가능한 날짜) 심어 두고, 그대로 두면 은행 게이트웨이가 며칠 뒤에야 보고했을 행 단위 결과를 바로 보여 줍니다.

    설치된 툴체인은 훨씬 더 깊은 게이트를 실행합니다: 필드 별칭 정규화를 포함한 레코드별 JSON Schema 검증, 규칙별 --explain 출력을 제공하는 다섯 가지 스킴 룰북(SEPA SCT, Instant, SDD Core, B2B, 국가 간 송금), 그리고 단 1바이트를 기록하기 전에 렌더링된 문서를 공식 ISO 20022 XSD로 최종 검증합니다. 열 개의 pain.001 버전과 pain.008.001.02 이 지원됩니다.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    위의 3단계는 시뮬레이션이 아닙니다: WebAssembly에서 Python 런타임을 부팅하고, 이 사이트에서 제공되는 공식 pain.001.001.09 스키마에 대해 xmlschema 를 실행합니다 — CLI가 적용하는 것과 같은 등급의 XSD 게이트입니다. CLI에만 남아 있는 것은 파이프라인의 나머지 부분입니다: JSON Schema 정규화, --explain 을 포함한 다섯 가지 스킴 룰북, 그리고 나머지 열 가지 메시지 정의입니다.
