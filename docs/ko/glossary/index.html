쉬운 말로 풀어쓴 ISO 20022 지급 용어집

쉬운 말로 풀어쓴 지급 용어 — 파일을 만드는 사람뿐 아니라 파일을 승인하는 사람을 위해.

3 분 소요 최종 검토 2026-07-26

목차

  1. 메시지
  2. 스킴과 룰북
  3. 식별자와 데이터
  4. 이 사이트에서 쓰는 도구 용어

이 사이트와 거래 은행의 채널 문서에 등장하는 용어를 쉬운 말로 정의했습니다. 엔지니어보다 재무 담당자와 운영팀을 먼저 염두에 두고 작성했습니다.

메시지#

pain.001 — Customer Credit Transfer Initiation. 고객이 하나 이상의 자금이체를 지시하기 위해 거래 은행에 보내는 XML 메시지입니다. "pain" 계열은 지급 개시(payment initiation)를 뜻하고, .001은 메시지 번호이며, 뒤에 붙는 버전(.001.09)이 스키마를 고정합니다.

pain.002 — Customer Payment Status Report. 보낸 pain.001 또는 pain.008에 대한 은행의 응답입니다. 수용, 부분 수용, 거절 여부를 거래별 ISO 사유 코드와 함께 알려 줍니다.

pain.008 — Customer Direct Debit Initiation. pain.001의 수납 쪽 쌍둥이 메시지입니다. 자금을 내보내는 대신, 위임(만데이트)에 따라 받을 자금을 회수합니다.

pacs.008 / pacs.009. 은행이 지시를 수용한 뒤 그 지시가 바뀌어 전달되는 은행 간 결제 메시지입니다. 기업이 직접 작성하는 일은 없으며, 은행끼리 주고받습니다.

camt.052 / camt.053 / camt.054. 계좌 보고용 메시지로 각각 일중 보고서, 일일 마감 명세서, 입출금 통지입니다. 대사 담당팀이 매일 아침 사용하는 것은 camt.053입니다.

MT101. pain.001이 대체하는 기존 SWIFT "Request for Transfer" 텍스트 메시지입니다. 은행 간 MT101 중계는 2026년 11월 14일에 폐지되고 pain.001.001.09로 대체됩니다. 기업과 은행 사이의 MT101은 각 은행의 재량으로만 유지됩니다.

스킴과 룰북#

SEPA SCT / SCT Inst. 유럽지급협의회(European Payments Council) 룰북이 규율하는 유로 자금이체 스킴으로, 일반형과 즉시형이 있습니다. 즉시 이체는 하루 24시간 몇 초 만에 결제됩니다.

SEPA SDD Core / B2B. 유로 자동이체 출금 스킴입니다. Core는 소비자용으로 환불 권리가 있고, B2B는 기업용으로 환불 권리가 없으며 위임 확인이 더 엄격합니다.

CBPR+. Cross-Border Payments and Reporting Plus의 약자로, SWIFT 환거래 은행 업무를 위해 ISO 20022 메시지를 규정한 이용 지침입니다. 사람들이 "SWIFT ISO 20022 전환"이라고 말할 때 가리키는 것이 CBPR+입니다.

HVPS+. 거액 지급 시스템(T2, CHAPS, Fedwire 등)을 위한 동일한 성격의 규정입니다.

CGI-MP. Common Global Implementation — Market Practice의 약자로, 기업이 여러 은행에서 pain 메시지를 사용하는 방식을 표준화해 하나의 파일 형식으로 여러 거래 은행을 상대할 수 있게 하는 협의체입니다.

Verification of Payee (VoP). 2025년 10월 9일부터 모든 SEPA 자금이체에 적용되는, EU가 의무화한 이름·IBAN 일치 확인입니다. 실행 시점에 PSP가 수행하며, 일치 여부는 채권자 데이터가 얼마나 정확한지에 달려 있습니다.

식별자와 데이터#

IBAN. 국제은행계좌번호(ISO 13616)로, mod-97 체크섬을 통해 스스로 검증됩니다. 숫자 두 자리가 뒤바뀐 것만으로도 제출 전에 발견할 수 있는 이유입니다.

BIC / BICFI. 금융기관의 ISO 9362 사업자 식별 코드입니다. XML 요소는 pain.001.001.03에서는 <BIC>이지만 버전 9부터는 <BICFI>입니다. 이 이름 변경은 버전 업그레이드 과정에서 실제 거절을 유발합니다.

LEI. 법인식별기호(ISO 17442)로, 20자리 글로벌 기업 식별자입니다. 300만 개 이상이 활성 상태이며, 규제 당국은 지급 업무에서 이를 점점 더 의무화하고 있습니다.

UETR. 종단 간 고유 거래 참조로, 환거래 은행 체인 전반에서 지급을 추적할 수 있게 해 주는 UUID입니다(SWIFT gpi).

구조화 주소 / 하이브리드 주소. 자유 텍스트 줄 대신 우편 주소를 개별 XML 요소(도로명, 도시, 우편번호, 국가)로 표현하는 방식입니다. 2026년 11월 14일부터 CBPR+는 완전히 비구조화된 주소를 거절합니다. 도시와 국가를 구조화하고 70자 주소 줄을 최대 두 개까지 덧붙이는 하이브리드 방식은 계속 유효합니다.

NbOfTxs / CtrlSum. 그룹 헤더의 통제 합계로, 거래 건수와 금액 합계입니다. 은행은 이를 다시 계산하며, 값이 어긋나면 파일이 반송됩니다. Pain001은 언제나 검증된 레코드에서 이 값을 도출합니다.

수수료 부담자. 수수료를 누가 내는지를 나타냅니다: DEBT(송금인), CRED(수취인), SHAR(분담), SLEV(스킴 규칙에 따름). 기존 MT의 OUR/BEN/SHA는 앞의 세 가지에 대응합니다.

송금 정보. "이 지급이 무엇에 대한 것인지"를 담는 필드로, 자유 텍스트(140자) 또는 구조화된 참조를 사용합니다. 대사 담당팀이 모두가 제대로 채워 주기를 가장 바라는 항목입니다.

이 사이트에서 쓰는 도구 용어#

XSD 검증. XML을 공식 ISO 20022 스키마 정의에 대해 확인하는 절차입니다. Pain001은 파일을 작성하기 전에 이를 반드시 통과해야 하는 관문으로 취급합니다.

MCP — Model Context Protocol. AI 어시스턴트가 외부 도구를 호출할 때 사용하는 개방형 표준입니다. pain001-mcp는 17개의 지급 도구를 모든 MCP 클라이언트에 로컬 stdio로 제공합니다.

LSP — Language Server Protocol. IDE 진단 기능의 바탕이 되는 편집기 연동 표준입니다. pain001-lsp는 이를 이용해 입력하는 동안 지급 파일을 검증합니다.

SBOM. 소프트웨어 자재 명세서로, 릴리스에 포함된 모든 의존성을 기계가 읽을 수 있게 정리한 목록입니다. Pain001 코어 릴리스에서는 CycloneDX 형식으로 생성됩니다.

빠진 용어가 있나요? 용어를 제안해 주세요. 이 용어집은 사람들이 실제로 묻는 질문을 따라 넓어집니다.
