Проблема#

Банки отклоняют некорректно сформированные платёжные файлы. Каждое отклонение стоит цикла исправления; исправление, не успевшее к дневному сроку приёма, стоит дня расчёта. Причины отклонений известны заранее — а значит, предотвратимы.

Срок#

14 ноября 2026 года, требование уровня сети: трансграничные платежи (CBPR+) с полностью неструктурированными адресами отклоняются, а устаревший межбанковский канал MT101 выводится из эксплуатации в пользу ISO 20022 pain.001 версии 9. Риск находится в основных данных клиентов. Источники: SWIFT; полные ссылки — на pain001.com/2026-iso20022-migration-trends.

Что делает Pain001#

Пакет с открытым исходным кодом, который превращает имеющиеся данные — таблицы, выгрузки из ERP, устаревшие файлы SWIFT — в готовые для банка платёжные файлы ISO 20022 и доказательно проверяет каждый файл по официальному своду правил банка (ISO 20022 XSD) до отправки. Работает полностью на вашей инфраструктуре: без выгрузки, без облака поставщика, без телеметрии.

Сколько это стоит#

Ничего — в любом масштабе, под открытыми лицензиями (Apache-2.0 / MIT). Коммерческий ориентир: SDK трансляции от SWIFT публично указан по цене €10,000–30,000 в год.

Доказательства#

Опубликованный перечень зависимостей (SBOM) · код со 100% покрытием ветвлений как CI-гейт · независимо оценённая цепочка поставок (OpenSSF Scorecard) · документация с доступностью WCAG 2.2 AAA · политика безопасности с конфиденциальным раскрытием. Всё проверяемо на pain001.com.

Просьба#

Попросите вашу команду платёжной инженерии запустить 60-секундное демо на pain001.com/try — оно валидирует образцовый пакет и доказывает его соответствие официальной схеме ISO 20022 в браузере, ничего не выгружая. Если оно выдержит проверку, установка по руководству занимает считанные минуты.
