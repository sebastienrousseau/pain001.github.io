Простые определения терминов, встречающихся на этом сайте и в канальной документации вашего банка. Написано в первую очередь для казначеев и операционных команд, во вторую — для инженеров.

Сообщения#

pain.001 — Customer Credit Transfer Initiation. XML-сообщение, которое клиент отправляет своему банку для поручения одного или нескольких кредитовых переводов. Семейство "pain" означает payment initiation; .001 — номер сообщения; завершающая версия (.001.09) фиксирует схему.

pain.002 — Customer Payment Status Report. Ответ банка на ваш pain.001 или pain.008: принято, принято частично или отклонено, с кодами причин ISO по каждой транзакции.

pain.008 — Customer Direct Debit Initiation. Близнец pain.001 со стороны взыскания: вы списываете причитающиеся вам средства по мандату, а не отправляете деньги.

pacs.008 / pacs.009. Межбанковские расчётные сообщения, в которые превращается ваша инструкция после принятия банком. Корпорации их никогда не составляют; ими обмениваются банки.

camt.052 / camt.053 / camt.054. Отчётность по счетам: внутридневной отчёт, выписка на конец дня и уведомление о дебете/кредите соответственно. camt.053 — то, что команды сверки читают каждое утро.

MT101. Устаревшее текстовое сообщение SWIFT "Request for Transfer", на смену которому приходит pain.001. Межбанковская ретрансляция MT101 выводится из эксплуатации 14 ноября 2026 года в пользу pain.001.001.09; MT101 от корпорации к банку сохраняется только на усмотрение каждого банка.

Схемы и своды правил#

SEPA SCT / SCT Inst. Евросхемы кредитовых переводов (стандартная и мгновенная), регулируемые сводами правил Европейского платёжного совета. Мгновенные переводы рассчитываются за секунды, круглосуточно.

SEPA SDD Core / B2B. Евросхемы прямого дебетования — Core для потребителей (с правом возврата), B2B для бизнеса (без права возврата, более строгие проверки мандатов).

CBPR+. Cross-Border Payments and Reporting Plus: руководства по использованию, профилирующие сообщения ISO 20022 для корреспондентского банкинга SWIFT. Когда говорят "миграция SWIFT на ISO 20022", имеют в виду CBPR+.

HVPS+. Аналогичное профилирование для систем крупных платежей (T2, CHAPS, Fedwire и им подобных).

CGI-MP. Common Global Implementation — Market Practice: группа, гармонизирующая использование корпорациями сообщений pain в разных банках, чтобы один формат файла подходил многим банковским партнёрам.

Verification of Payee (VoP). Обязательная в ЕС проверка соответствия имени и IBAN, применяемая ко всем кредитовым переводам SEPA с 9 октября 2025 года. Выполняется PSP в момент исполнения; совпадение определяют чистые данные о кредиторе.

Идентификаторы и данные#

IBAN. Международный номер банковского счёта (ISO 13616), самопроверяемый через контрольную сумму mod-97 — поэтому одна переставленная цифра обнаруживается до отправки.

BIC / BICFI. Идентификационный код финансового учреждения по ISO 9362. XML-элемент называется в pain.001.001.03, но начиная с версии 9 — переименование, вызывающее реальные отклонения при обновлении версий.

LEI. Legal Entity Identifier (ISO 17442) — глобальный 20-символьный идентификатор компании. Активно более 3 миллионов, и регуляторы всё чаще требуют их в платежах.

UETR. Unique End-to-end Transaction Reference — UUID, позволяющий отследить платёж по всей корреспондентской цепочке (SWIFT gpi).

Структурированный / гибридный адрес. Почтовые адреса как отдельные XML-элементы (улица, город, индекс, страна) против строк свободного текста. С 14 ноября 2026 года CBPR+ отклоняет полностью неструктурированные адреса; гибрид — структурированные город и страна плюс до двух адресных строк по 70 символов — остаётся допустимым.

NbOfTxs / CtrlSum. Контрольные итоги заголовка группы: число транзакций и сумма. Банки пересчитывают их; если ваши расходятся, файл возвращается. Pain001 всегда выводит их из проверенных записей.

Плательщик комиссии. Кто платит комиссии: DEBT (отправитель), CRED (получатель), SHAR (поровну), SLEV (по правилам схемы). Устаревшие MT-коды OUR/BEN/SHA соответствуют первым трём.

Назначение платежа (remittance information). Поле "за что этот платёж" — свободный текст (140 символов) или структурированные ссылки. То, что команды сверки мечтают видеть заполненным как следует.

Инструментальные термины на этом сайте#

Валидация по XSD. Проверка XML по официальному определению схемы ISO 20022. Pain001 считает её обязательным шлюзом перед записью любого файла.

MCP — Model Context Protocol. Открытый стандарт, через который AI-ассистенты вызывают внешние инструменты. pain001-mcp предоставляет 17 платёжных инструментов любому MCP-клиенту, локально по stdio.

LSP — Language Server Protocol. Стандарт интеграции с редакторами, лежащий в основе диагностик IDE. pain001-lsp использует его для проверки платёжных файлов по мере ввода.

SBOM. Software Bill of Materials — машиночитаемый перечень всех зависимостей релиза, генерируемый в формате CycloneDX для релизов ядра Pain001.
