Glossário de pagamentos ISO 20022 em linguagem clara

O vocabulário de pagamentos em linguagem clara — para quem aprova os arquivos, não só para quem os gera.

3 min de leitura Última revisão 2026-07-26

Sumário

  1. Mensagens

Definições em linguagem clara dos termos que aparecem neste site e na documentação de canal do seu banco. Escritas primeiro para tesoureiros e equipes de operações, depois para engenheiros.

Mensagens#

pain.001 — Customer Credit Transfer Initiation. A mensagem XML que um cliente envia ao banco para ordenar uma ou mais transferências de crédito. A família "pain" é a payment initiation; .001 é o número da mensagem; a versão final (.001.09) fixa o esquema.

pain.002 — Customer Payment Status Report. A resposta do banco ao seu pain.001 ou pain.008: aceito, parcialmente aceito ou rejeitado, com códigos de motivo ISO por transação.

pain.008 — Customer Direct Debit Initiation. O gêmeo de cobrança do pain.001: você puxa fundos que lhe são devidos sob um mandato, em vez de enviar fundos.

pacs.008 / pacs.009. As mensagens de liquidação interbancária em que sua instrução se transforma quando o banco a aceita. Empresas nunca as redigem; os bancos as trocam entre si.

camt.052 / camt.053 / camt.054. Relatórios de conta: relatório intradiário, extrato de fim de dia e notificação de débito/crédito, respectivamente. O camt.053 é o que as equipes de conciliação consomem toda manhã.

MT101. A mensagem de texto legada da SWIFT "Request for Transfer" que o pain.001 substitui. O relay interbancário do MT101 será descomissionado em 14 de novembro de 2026 em favor do pain.001.001.09; o MT101 empresa-banco persiste apenas a critério de cada banco.

Esquemas e rulebooks#

SEPA SCT / SCT Inst. Os esquemas de transferência de crédito em euro (padrão e instantâneo) regidos pelos rulebooks do European Payments Council. As transferências instantâneas liquidam em segundos, 24 horas por dia.

SEPA SDD Core / B2B. Os esquemas de débito direto em euro — Core para consumidores (com direito a reembolso), B2B para empresas (sem direito a reembolso, verificações de mandato mais rígidas).

CBPR+. Cross-Border Payments and Reporting Plus: as diretrizes de uso que perfilam as mensagens ISO 20022 para o correspondent banking da SWIFT. Quando se fala em "migração da SWIFT para ISO 20022", trata-se do CBPR+.

HVPS+. O perfilamento equivalente para sistemas de pagamentos de alto valor (T2, CHAPS, Fedwire e pares).

CGI-MP. Common Global Implementation — Market Practice: o grupo que harmoniza como as empresas usam mensagens pain entre bancos, para que um único formato de arquivo atenda a muitos parceiros bancários.

Verification of Payee (VoP). A verificação de correspondência nome/IBAN exigida pela UE, aplicada a todas as transferências de crédito SEPA desde 9 de outubro de 2025. Feita pelo PSP no momento da execução; dados limpos do credor determinam se há correspondência.

Identificadores e dados#

IBAN. International Bank Account Number (ISO 13616), autoverificável por um checksum mod-97 — razão pela qual um único dígito transposto é detectável antes do envio.

BIC / BICFI. O Business Identifier Code ISO 9362 de uma instituição financeira. O elemento XML é no pain.001.001.03, mas a partir da versão 9 — uma renomeação que causa rejeições reais durante upgrades de versão.

LEI. Legal Entity Identifier (ISO 17442) — o identificador global de empresas com 20 caracteres. Há mais de 3 milhões ativos, e os reguladores os exigem cada vez mais nos pagamentos.

UETR. Unique End-to-end Transaction Reference — o UUID que permite rastrear um pagamento por toda a cadeia de correspondentes (SWIFT gpi).

Endereço estruturado / híbrido. Endereços postais como elementos XML discretos (rua, cidade, código postal, país) em contraste com linhas de texto livre. A partir de 14 de novembro de 2026, o CBPR+ rejeita endereços totalmente não estruturados; o híbrido — cidade e país estruturados mais até duas linhas de endereço de 70 caracteres — permanece válido.

NbOfTxs / CtrlSum. Os totais de controle do cabeçalho de grupo: contagem de transações e soma dos valores. Os bancos os recalculam; se os seus divergirem, o arquivo volta. O Pain001 sempre os deriva dos registros validados.

Charge bearer. Quem paga as tarifas: DEBT (remetente), CRED (beneficiário), SHAR (compartilhadas), SLEV (conforme as regras do esquema). Os legados MT OUR/BEN/SHA mapeiam para os três primeiros.

Informações de remessa. O campo "para que serve este pagamento" — texto livre (140 caracteres) ou referências estruturadas. Aquilo que as equipes de conciliação gostariam que todos preenchessem direito.

Termos de ferramentas usados neste site#

Validação XSD. A verificação do XML contra a definição de esquema oficial ISO 20022. O Pain001 a trata como um portão rígido antes de qualquer arquivo ser gravado.

MCP — Model Context Protocol. O padrão aberto pelo qual assistentes de IA chamam ferramentas externas. O pain001-mcp expõe 17 ferramentas de pagamento a qualquer cliente MCP, localmente via stdio.

LSP — Language Server Protocol. O padrão de integração com editores por trás dos diagnósticos de IDE. O pain001-lsp o utiliza para validar arquivos de pagamento enquanto você digita.

SBOM. Software Bill of Materials — um inventário legível por máquina de cada dependência de uma release, gerado no formato CycloneDX para as releases do núcleo do Pain001.
