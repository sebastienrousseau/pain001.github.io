Demo interactiv

Încercați Pain001 în browser

Trageți un fișier CSV, folosiți exemplul sau lipiți propriile înregistrări — validarea rulează instantaneu, integral în browserul dumneavoastră, și nimic nu vă părăsește vreodată calculatorul.

Cum vă ajută acest validator

  • ✓Testați datele de plată față de verificările aplicate de bănci — câmpuri obligatorii, cifre de control IBAN, structura BIC, totaluri de control
  • ✓Generați un fișier pain.001.001.09 de transfer credit funcțional, pe care îl puteți inspecta, copia sau descărca
  • ✓Verificați rezultatul față de schema oficială ISO 20022 — XSD-ul autentic, validat în browserul dumneavoastră

Informații importante

  • Nimic nu este încărcat pe server. Fișierul este citit de propriul browser și nu vă părăsește niciodată calculatorul — nu există server, stocare sau telemetrie. Sigur pentru date reale, deși datele de test mascate rămân întotdeauna o bună practică.
  • Doar un instrument de testare. Fișierele nu sunt niciodată trimise spre procesare și nimic din ce faceți aici nu poate genera o plată.
  • Coloane așteptate: payment_id, payment_amount, currency, numele / IBAN / BIC ale plătitorului și beneficiarului, requested_execution_date — separatorii virgulă, punct și virgulă și tab sunt detectați automat. Descărcați mai jos un exemplu pe care să îl folosiți ca șablon pentru propriul export.
  • Fără costuri. Acest instrument, și întregul lanț de instrumente din spatele lui, sunt gratuite și open source.

Verificați personal

"Nimic nu este încărcat" este o afirmație pe care o puteți verifica în două minute:

  1. Deschideți DevTools → Network, apoi folosiți demo-ul. Singurele cereri sunt GET-uri same-origin pentru resursele acestei pagini, motorul WASM și schemă — niciuna nu transportă datele dumneavoastră.
  2. Rulați o dată poarta XSD, apoi comutați DevTools pe Offline (sau opriți Wi-Fi-ul). Întregul demo — inclusiv poarta oficială a schemei — funcționează în continuare: un service worker păstrează totul în cache după prima utilizare.
  3. Și această pagină este open source — logica demo-ului este un singur modul fără dependențe, pe care îl puteți citi integral.

Nu există niciun script de analiză, niciun serviciu de raportare a erorilor, niciun font terț și niciun endpoint de raportare CSP — raportarea în sine ar fi o conexiune de ieșire.

Verificați-l față de XSD-ul oficial ISO 20022

Pașii 1–2 rulează verificări rapide, scrise manual. Acest pas rulează originalul: un mediu de execuție Python (prin WebAssembly) care rulează xmlschema față de schema oficială pain.001.001.09 — aceeași clasă de validare pe care o efectuează CLI-ul. Motorul de ~13 MB este servit de pe acest site și descărcat o singură dată, la cerere (descărcarea începe discret imediat ce pasul 2 produce XML valid).

Generați mai întâi XML la pasul 2 — poarta XSD validează acel rezultat.

    Totul pe această pagină rulează în browserul dumneavoastră — nimic nu este încărcat, stocat sau trimis undeva. Acest demo implementează un subset al pipeline-ului (câmpuri obligatorii, IBAN mod-97, structura BIC, formate de sumă și dată, totaluri recalculate NbOfTxs/CtrlSum de control). Pasul 3 rulează poarta oficială XSD chiar aici, prin WebAssembly. Lanțul de instrumente instalat adaugă în plus validare JSON Schema și cinci seturi de reguli pentru scheme de plată — instalați CLI-ul pentru pipeline-ul complet.

    Ce arată acest demo — și ce adaugă pipeline-ul real

    Fiecare lot exemplu poate fi și descărcat ca fișier CSV, pentru a-l folosi ca șablon pentru exportul din propriul ERP sau tabel de calcul — rândul de antet este contractul.

    Demo-ul de mai sus implementează stratul fail-fast al pipeline-ului Pain001: verificări ale câmpurilor obligatorii, cifre de control IBAN mod-97 conform ISO 13616, structura BIC conform ISO 9362, formate de sumă și dată și totaluri de control (NbOfTxs, CtrlSum) recalculate din înregistrări, nu preluate pe încredere. Încercați meniul "Introduceți o eroare…" — fiecare scenariu plantează exact un defect realist (o cifră IBAN inversată, un BIC malformat, o coloană lipsă, o sumă europeană cu virgulă zecimală, o dată imposibilă) și vă arată constatarea la nivel de rând pe care poarta de acces a unei bănci ar raporta-o altfel abia după câteva zile.

    Lanțul de instrumente instalat rulează o poartă mult mai profundă: validare JSON Schema pentru fiecare înregistrare, cu normalizarea aliasurilor de câmp, cinci seturi de reguli pentru scheme de plată (SEPA SCT, Instant, SDD Core, B2B, transfrontalier) cu rezultat --explain regulă cu regulă și validarea finală a documentului redat față de XSD-ul oficial ISO 20022 înainte de a se scrie un singur byte. Sunt acceptate zece versiuni pain.001 și pain.008.001.02.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Pasul 3 de mai sus nu este o simulare: pornește un mediu de execuție Python în WebAssembly și rulează xmlschema față de schema oficială pain.001.001.09, servită de pe acest site — aceeași clasă de poartă XSD pe care o aplică CLI-ul. Ce rămâne exclusiv în CLI este restul pipeline-ului: normalizarea JSON Schema, cele cinci seturi de reguli cu --explain, și celelalte zece definiții de mesaje.
