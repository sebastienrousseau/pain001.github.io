परस्परसंवादी डेमो

Pain001 तुमच्या ब्राउझरमध्ये वापरून पहा

CSV फाइल टाका, नमुना वापरा किंवा तुमच्या स्वतःच्या नोंदी पेस्ट करा — पडताळणी त्वरित, पूर्णपणे तुमच्या ब्राउझरमध्येच चालते; काहीही तुमच्या संगणकाबाहेर जात नाही.

हे पडताळणी साधन तुम्हाला कशी मदत करते

  • ✓बँका लागू करत असलेल्या तपासण्यांविरुद्ध पेमेंट डेटाची चाचणी करा — आवश्यक फील्ड, IBAN चेकसम, BIC रचना, नियंत्रण बेरजा
  • ✓तुम्ही तपासू, कॉपी करू किंवा डाउनलोड करू शकाल अशी कार्यरत pain.001.001.09 क्रेडिट-हस्तांतरण फाइल तयार करा
  • ✓अधिकृत ISO 20022 स्कीमाविरुद्ध निकाल सिद्ध करा — अस्सल XSD, तुमच्या ब्राउझरमध्येच पडताळलेले

महत्त्वाची माहिती

  • काहीही अपलोड होत नाही. तुमची फाइल तुमच्याच ब्राउझरद्वारे वाचली जाते आणि ती तुमच्या संगणकाबाहेर कधीही जात नाही — सर्व्हर नाही, साठवण नाही, टेलिमेट्री नाही. खऱ्या डेटासाठीही सुरक्षित; तरीही मास्क केलेला चाचणी डेटा वापरणे नेहमीच चांगली पद्धत आहे.
  • केवळ चाचणी साधन. फाइली कधीही प्रक्रियेसाठी सादर केल्या जात नाहीत; येथे तुम्ही केलेल्या कोणत्याही कृतीतून कोणतेही पेमेंट होऊ शकत नाही.
  • अपेक्षित स्तंभ: payment_id, payment_amount, currency, देयकर्ता आणि प्राप्तकर्ता नाव / IBAN / BIC, requested_execution_date — स्वल्पविराम, अर्धविराम आणि टॅब विभाजक आपोआप ओळखले जातात. तुमच्या स्वतःच्या निर्यातीसाठी टेम्पलेट म्हणून वापरण्यासाठी खाली नमुना डाउनलोड करा.
  • कोणतेही शुल्क नाही. हे साधन आणि त्यामागील संपूर्ण टूलचेन विनामूल्य आणि मुक्त-स्रोत आहेत.

स्वतः पडताळून पहा

"काहीही अपलोड होत नाही" हा दावा तुम्ही दोन मिनिटांत स्वतः तपासू शकता:

  1. DevTools → Network उघडा, नंतर डेमो वापरा. केवळ या पानाची संसाधने, WASM इंजिन आणि स्कीमासाठीच्या same-origin GET विनंत्या असतात — कोणतीही तुमचा डेटा वाहून नेत नाही.
  2. XSD गेट एकदा चालवा, नंतर DevTools Offline वर स्विच करा (किंवा Wi-Fi बंद करा). अधिकृत स्कीमा गेटसह संपूर्ण डेमो अजूनही चालतो: पहिल्या वापरानंतर एक service worker सर्व काही कॅशे करतो.
  3. हे पानही मुक्त-स्रोत आहे — डेमोचे लॉजिक हे अवलंबित्वमुक्त एकच मॉड्यूल आहे, जे तुम्ही संपूर्ण वाचू शकता.

येथे कोणतीही अ‍ॅनालिटिक्स स्क्रिप्ट नाही, त्रुटी-अहवाल सेवा नाही, तृतीय-पक्ष फॉन्ट नाही आणि CSP रिपोर्ट एंडपॉइंटही नाही — अहवाल पाठवणे हेच एक बाह्य कनेक्शन ठरले असते.

1

तुमचा पेमेंट डेटा जोडा

CSV फाइल येथे ड्रॅग करा — किंवा ब्राउझ करण्यासाठी क्लिक करा

कमाल 2 MB · तुमच्या ब्राउझरद्वारे स्थानिक पातळीवर वाचली जाते, कधीही अपलोड होत नाही

तुमचे स्वतःचे टेम्पलेट म्हणून वापरण्यासाठी नमुना डाउनलोड करा: SEPA क्रेडिट हस्तांतरण · सीमापार · 20-ओळींचा बॅच

2

पडताळणी निकाल & तयार केलेले XML

पायरी 1 मध्ये डेटा जोडा — पडताळणी आपोआप चालते.

काय तपासले गेले
ISO 20022 स्कीमा —

पडताळणी केलेला pain.001.001.09 दस्तऐवज येथे दिसेल — चरण 1 मध्ये डेटा जोडा.
3

अधिकृत ISO 20022 XSD विरुद्ध सिद्ध करा

पायऱ्या 1–2 जलद, हाताने लिहिलेल्या तपासण्या चालवतात. ही पायरी अस्सल गोष्टच चालवते: एक Python रनटाइम (WebAssembly द्वारे) xmlschema अधिकृत pain.001.001.09 स्कीमाविरुद्ध चालवते — CLI करत असलेल्या पडताळणीचाच वर्ग. ~13 MB इंजिन याच साइटवरून दिले जाते आणि तुम्ही मागाल तेव्हा एकदाच डाउनलोड होते (पायरी 2 वैध XML तयार करताच ते शांतपणे डाउनलोड होऊ लागते).

आधी पायरी 2 मध्ये XML तयार करा — XSD गेट त्याच आउटपुटची पडताळणी करते.

    या पानावरील सर्व काही तुमच्या ब्राउझरमध्येच चालते — काहीही अपलोड, साठवले किंवा कोठेही पाठवले जात नाही. हा डेमो पाइपलाइनचा एक उपसंच अंमलात आणतो (आवश्यक फील्ड, IBAN mod-97, BIC रचना, रक्कम आणि तारीख स्वरूपे, पुनर्गणित NbOfTxs/CtrlSum नियंत्रण बेरजा). पायरी 3 अधिकृत XSD गेट WebAssembly द्वारे येथेच चालवते. स्थापित टूलचेन त्यावर JSON Schema पडताळणी आणि पाच योजना नियमपुस्तिका जोडते — संपूर्ण पाइपलाइनसाठी CLI स्थापित करा.

    हा डेमो काय दाखवतो — आणि खरी पाइपलाइन काय जोडते

    प्रत्येक नमुना बॅच तुमच्या स्वतःच्या ERP किंवा स्प्रेडशीट निर्यातीसाठी टेम्पलेट म्हणून CSV फाइल म्हणूनही डाउनलोड करता येतो — शीर्षक ओळ हाच करार आहे.

    वरील डेमो Pain001 पाइपलाइनचा fail-fast स्तर अंमलात आणतो: आवश्यक-फील्ड तपासण्या, ISO 13616 mod-97 IBAN चेकसम, ISO 9362 BIC रचना, रक्कम आणि तारीख स्वरूपे, आणि गृहीत न धरता नोंदींवरून पुनर्गणित केलेल्या नियंत्रण बेरजा (NbOfTxs, CtrlSum). "त्रुटी समाविष्ट करा…" मेनू वापरून पहा — प्रत्येक परिस्थिती नेमका एक वास्तववादी दोष (उलटलेला IBAN अंक, चुकीच्या रचनेचा BIC, गहाळ स्तंभ, युरोपीय स्वल्पविराम-दशांश रक्कम, अशक्य तारीख) पेरते आणि बँकेचे गेटवे अन्यथा काही दिवसांनी कळवेल तो ओळ-स्तरीय निष्कर्ष तुम्हाला दाखवते.

    स्थापित टूलचेन खूप खोल गेट चालवते: फील्ड-उपनाम सामान्यीकरणासह प्रत्येक नोंदीसाठी JSON Schema पडताळणी, नियमनिहाय --explain आउटपुटसह पाच योजना नियमपुस्तिका (SEPA SCT, Instant, SDD Core, B2B, सीमापार), आणि एकही बाइट लिहिण्यापूर्वी तयार दस्तऐवजाची अधिकृत ISO 20022 XSD विरुद्ध अंतिम पडताळणी. दहा pain.001 आवृत्त्या आणि pain.008.001.02 समर्थित आहेत.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    वरील पायरी 3 हे अनुकरण नाही: ती WebAssembly मध्ये Python रनटाइम सुरू करते आणि याच साइटवरून दिल्या जाणाऱ्या अधिकृत pain.001.001.09 स्कीमाविरुद्ध xmlschema चालवते — CLI लागू करत असलेल्या XSD गेटचाच वर्ग. उर्वरित पाइपलाइन मात्र केवळ CLI मध्ये आहे: JSON Schema सामान्यीकरण, --explain सह पाच योजना नियमपुस्तिका, आणि इतर दहा संदेश व्याख्या.
