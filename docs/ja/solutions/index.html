トレジャリー&財務#

銀行は、ERPが警告してくれなかった理由でファイルを却下します。IBANの数字の入れ替わり、一致しなくなったコントロールトータル、許容されなくなった住所フォーマットなどです。Pain001は、こうした失敗を提出前、お手元の段階で顕在化させます——すべてのファイルは提出前に銀行の公式ルールブック(ISO 20022 XSD)に照らして証明され、ペイメントライフサイクルガイドは、起票から照合までの間で各チェックがどこに位置するかを示します。用語に馴染みがなければ用語集からどうぞ。平易な定義は、エンジニアではなく業務側の視点で書かれています。

CFO&取締役会#

2つの数字が判断の枠組みになります。2026年11月14日:非構造化住所を含むクロスボーダー決済がネットワークレベルで却下され始める日です——リスクは銀行接続ではなく、顧客マスターデータの中にあります。年額€10,000–30,000:最も近い商用トランスレーションSDKの公表価格であり、対するPain001はオープンライセンスの下、どの規模でも恒久的にゼロです。ガバナンス上の問い——監査可能性、データ所在、サプライチェーンの証拠——には、保証の言葉ではなく成果物でお答えします:公開済みのSBOM、セキュリティポリシー、そしてお客様のインフラから一切出ない処理です。1ページのエグゼクティブブリーフは、そのまま転送していただけるように書かれています。

ペイメントオペレーション#

皆様の日常はレスポンスファイルの中にあります。Pain001はループを端から端まで閉じます:CIで明確に合否が出る--dry-runの提出前チェック、ルールごとに解説されたスキームルールブック(SEPAおよびクロスボーダー)、返ってきた内容を読み解くためのpain.002理由コードリファレンス、そして銀行のレスポンスやcamt.053ステートメントをパイプラインでルーティングできる構造化データに変換するパーサーです。ブラウザデモは、Pain001が排除する失敗クラスを確認する最速の方法です——ワンクリックの「エラーを挿入」シナリオも含まれます。

エンジニアリング&AI#

型付きのPython API、意味のある終了コードを返すCLI、RESTマイクロサービス、そしてローダー、バリデーター、スキーム、ライター向けのプラグインポイント——技術リファレンスがすべてのフラグとエンドポイントを網羅し、コードは行・ブランチカバレッジ100%を厳格なCIゲートとして維持しています。エージェントで構築される場合:pain001-mcpはこのカテゴリー唯一のModel Context Protocolサーバーで、エージェントがローカルに呼び出せる17個の読み取り専用ツールを備え、pain001-lspによるエディター診断で人間がループに残ります。

Pain001
