ブラウザで Pain001 を試す

CSV をドロップするか、サンプルを使うか、ご自身のレコードを貼り付けてください — 検証はすべてブラウザ内で即座に実行され、データがお使いの端末の外に出ることは一切ありません。

このバリデーターがお役に立つ場面

  • ✓銀行が適用するチェックに対して決済データをテストできます — 必須項目、IBAN チェックサム、BIC 構造、コントロール合計
  • ✓確認・コピー・ダウンロードできる、実際に動作する pain.001.001.09 クレジットトランスファーファイルを生成します
  • ✓結果を公式の ISO 20022 スキーマで証明します — 本物の XSD をブラウザ内で検証します

重要なご案内

  • 何もアップロードされません。ファイルはお使いのブラウザ自身によって読み込まれ、端末の外に出ることは決してありません — サーバーも、保存も、テレメトリーもありません。実データでも安全ですが、マスキングしたテストデータのご利用を常にお勧めします。
  • テスト専用ツールです。ファイルが処理のために送信されることはなく、ここでの操作から支払いが発生することは一切ありません。
  • 想定される列: payment_id, payment_amount, currency, 債務者および債権者の名前 / IBAN / BIC, requested_execution_date — カンマ、セミコロン、タブの区切り文字は自動検出されます。ご自身のエクスポートのテンプレートとして、下のサンプルをダウンロードしてください。
  • 料金はかかりません。このツールも、その背後にあるフルツールチェーンも、無料のオープンソースです。

ご自身でご確認ください

「何もアップロードされません」という主張は、2分でご自身で検証できます:

  1. DevTools → Network を開いてからデモをお使いください。発生するリクエストは、このページのアセット、WASM エンジン、スキーマを取得する same-origin の GET のみで、お客様のデータを送信するものは一つもありません。
  2. XSD ゲートを一度実行してから、DevTools を Offline に切り替えてください(または Wi-Fi をオフにしてください)。公式スキーマゲートを含むデモ全体が引き続き動作します: サービスワーカーが初回利用後にすべてをキャッシュするためです。
  3. このページ自体もオープンソースです — デモのロジックは依存関係のない単一モジュールで、全文をお読みいただけます。

アナリティクススクリプトも、エラーレポートサービスも、サードパーティフォントも、CSP レポートエンドポイントもありません — レポート送信自体が外向きの接続になってしまうためです。

3

公式の ISO 20022 XSD で証明する

ステップ1〜2は、手書きの高速チェックを実行します。このステップでは本物を実行します: Python ランタイム(WebAssembly 経由)が xmlschema を公式の pain.001.001.09 スキーマに対して実行します — CLI が行うものと同じクラスの検証です。約 13 MB のエンジンはこのサイトから配信され、 リクエスト時に一度だけダウンロードされます(ステップ2で有効な XML が生成されると、 すぐに静かにダウンロードが始まります)。

先にステップ2で XML を生成してください — XSD ゲートはその出力を検証します。

    このページのすべてはブラウザ内で実行されます — 何もアップロード、保存、送信されません。 このデモはパイプラインの一部(必須項目、IBAN mod-97、BIC 構造、金額 と日付の形式、再計算された NbOfTxs/CtrlSum コントロール合計)を実装しています。ステップ3は WebAssembly により公式 XSD ゲートをこの場で実行します。インストール版ツールチェーンは さらに JSON Schema 検証と5つのスキームルールブックを追加します — 完全なパイプラインには CLI をインストールしてください。

    このデモが示すもの — そして実際のパイプラインが追加するもの

    各サンプルバッチは CSV ファイルとしてもダウンロードでき、ご自身の ERP やスプレッドシートのエクスポートのテンプレートとしてお使いいただけます — ヘッダー行が契約です。

    上のデモは Pain001 パイプラインのフェイルファスト層を実装しています: 必須項目チェック、ISO 13616 mod-97 の IBAN チェックサム、ISO 9362 の BIC 構造、金額と日付の形式、そしてレコードから再計算される(鵜呑みにしない)コントロール合計 (NbOfTxs, CtrlSum) です。「エラーを挿入する…」メニューをお試しください — 各シナリオは現実的な欠陥をちょうど1つ(入れ替わった IBAN の数字、不正な形式の BIC、欠落した列、欧州式のカンマ小数の金額、あり得ない日付)仕込み、放置すれば銀行のゲートウェイが数日後に報告するはずの行レベルの検出結果をその場で表示します。

    インストール版ツールチェーンは、はるかに深いゲートを実行します: フィールドエイリアス正規化を伴うレコードごとの JSON Schema 検証、ルールごとの --explain 出力を伴う5つのスキームルールブック(SEPA SCT、Instant、SDD Core、B2B、クロスボーダー)、そして1バイトも書き出す前に、レンダリングされた文書を公式の ISO 20022 XSD で最終検証します。10個の pain.001 バージョンと pain.008.001.02 がサポートされています。

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    上のステップ3はシミュレーションではありません: WebAssembly で Python ランタイムを起動し、このサイトから配信される公式の pain.001.001.09 スキーマに対して xmlschema を実行します — CLI が適用するものと同じクラスの XSD ゲートです。CLI のみに残るのはパイプラインの残りの部分です: JSON Schema の正規化、--explain を伴う5つのスキームルールブック、そして他の10種類のメッセージ定義です。
