Interaktibong demo

Subukan ang Pain001 sa Inyong Browser

Mag-drop ng CSV, gamitin ang sample, o i-paste ang sarili ninyong mga rekord — agad na tumatakbo ang validation, ganap na nasa inyong browser, at walang datos na umaalis sa inyong makina.

Paano kayo tinutulungan ng validator na ito

  • ✓Subukan ang datos ng pagbabayad laban sa mga pagsusuring ginagamit ng mga bangko — mga kinakailangang field, checksum ng IBAN, istruktura ng BIC, mga control total
  • ✓Bumuo ng gumaganang pain.001.001.09 credit-transfer file na maaari ninyong suriin, kopyahin, o i-download
  • ✓Patunayan ang resulta laban sa opisyal na ISO 20022 schema — ang tunay na XSD, na-validate sa inyong browser

Mahalagang impormasyon

  • Walang ina-upload. Binabasa ng sarili ninyong browser ang inyong file at hindi ito kailanman umaalis sa inyong makina — walang server, walang storage, walang telemetry. Ligtas para sa totoong datos, bagaman laging mabuting kasanayan ang paggamit ng naka-mask na test data.
  • Pangsubok na kasangkapan lamang. Hindi kailanman isinusumite ang mga file para iproseso at walang anumang pagbabayad na maaaring magresulta mula sa anumang gagawin ninyo rito.
  • Inaasahang mga column: payment_id, payment_amount, currency, pangalan ng debtor at creditor / IBAN / BIC, requested_execution_date — awtomatikong natutukoy ang mga delimiter na comma, semicolon, at tab. Mag-download ng sample sa ibaba upang gamitin bilang template para sa sarili ninyong export.
  • Walang bayad. Ang kasangkapang ito, at ang buong toolchain sa likod nito, ay libre at open source.

Beripikahin ninyo mismo

Ang "Walang ina-upload" ay isang pahayag na maaari ninyong subukin sa loob ng dalawang minuto:

  1. Buksan ang DevTools → Network, pagkatapos ay gamitin ang demo. Ang tanging mga request ay same-origin na GET para sa mga asset ng pahinang ito, sa WASM engine, at sa schema — wala ni isang nagdadala ng inyong datos.
  2. Patakbuhin nang isang beses ang XSD gate, pagkatapos ay ilipat ang DevTools sa Offline (o patayin ang Wi-Fi). Gumagana pa rin ang buong demo — kasama ang opisyal na schema gate — dahil isang service worker ang nagka-cache ng lahat pagkatapos ng unang paggamit.
  3. Open source din ang pahinang ito — ang lohika ng demo ay isang module na walang dependency na maaari ninyong basahin nang buo.

Walang analytics script, walang serbisyo sa pag-uulat ng error, walang third-party na font, at walang CSP report endpoint — ang pag-uulat mismo ay magiging papalabas na koneksyon.

3

Patunayan ito laban sa opisyal na ISO 20022 XSD

Ang hakbang 1–2 ay nagpapatakbo ng mabibilis at manu-manong isinulat na pagsusuri. Ang hakbang na ito ang nagpapatakbo ng tunay: isang Python runtime (sa pamamagitan ng WebAssembly) na nagsasagawa ng xmlschema laban sa opisyal na pain.001.001.09 schema — kaparehong uri ng validation na ginagawa ng CLI. Ang ~13 MB na engine ay inihahatid mula sa site na ito at isang beses lang dina-download, kapag hiniling ninyo (tahimik itong nagsisimulang mag-download sa sandaling makabuo ng valid na XML ang hakbang 2).

Bumuo muna ng XML sa hakbang 2 — vina-validate ng XSD gate ang output na iyon.

    Lahat ng nasa pahinang ito ay tumatakbo sa inyong browser — walang ina-upload, iniimbak, o ipinapadala saanman. Ipinatutupad ng demo na ito ang bahagi ng pipeline (mga kinakailangang field, IBAN mod-97, istruktura ng BIC, format ng halaga at petsa, muling kinompyut na NbOfTxs/CtrlSum control total). Pinapatakbo ng hakbang 3 ang opisyal na XSD gate dito mismo sa pamamagitan ng WebAssembly. Ang naka-install na toolchain ay nagdaragdag ng JSON Schema validation at limang scheme rulebook sa ibabaw nito — i-install ang CLI para sa kumpletong pipeline.

    Ano ang ipinapakita ng demo na ito — at ano ang idinaragdag ng tunay na pipeline

    Ang bawat sample na batch ay maaari ring i-download bilang CSV file upang gamitin bilang template para sa sarili ninyong ERP o spreadsheet export — ang header row ang kontrata.

    Ipinatutupad ng demo sa itaas ang fail-fast na layer ng pipeline ng Pain001: pagsusuri ng mga kinakailangang field, ISO 13616 mod-97 na checksum ng IBAN, ISO 9362 na istruktura ng BIC, format ng halaga at petsa, at mga control total (NbOfTxs, CtrlSum) na muling kinokompyut mula sa mga rekord sa halip na basta pagkatiwalaan. Subukan ang menu na "Maglagay ng error…" — bawat scenario ay naglalagay ng eksaktong isang makatotohanang depekto (nabaligtad na digit ng IBAN, maling anyo ng BIC, nawawalang column, halagang may European na comma-decimal, imposibleng petsa) at ipinapakita ang natuklasang nasa antas ng hilera na kung hindi ay iuulat lamang ng gateway ng bangko pagkalipas ng ilang araw.

    Ang naka-install na toolchain ay nagpapatakbo ng mas malalim na gate: JSON Schema validation bawat rekord na may normalisasyon ng field alias, limang scheme rulebook (SEPA SCT, Instant, SDD Core, B2B, cross-border) na may --explain output bawat panuntunan, at panghuling validation ng nabuong dokumento laban sa opisyal na ISO 20022 XSD bago maisulat ang kahit isang byte. Sampung pain.001 bersyon at pain.008.001.02 ang sinusuportahan.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Ang hakbang 3 sa itaas ay hindi simulation: nagbo-boot ito ng Python runtime sa WebAssembly at nagpapatakbo ng xmlschema laban sa opisyal na pain.001.001.09 schema, na inihahatid mula sa site na ito — kaparehong uri ng XSD gate na ginagamit ng CLI. Ang nananatiling nasa CLI lamang ay ang natitirang bahagi ng pipeline: normalisasyon ng JSON Schema, ang limang scheme rulebook na may --explain, at ang iba pang sampung message definition.
