Інтерактивна демонстрація

Спробуйте Pain001 у своєму браузері

Перетягніть файл CSV, скористайтеся зразком або вставте власні записи — валідація виконується миттєво, повністю у вашому браузері, і жодні дані не залишають ваш комп’ютер.

Чим цей валідатор корисний вам

  • ✓Перевіряйте платіжні дані за тими самими правилами, що їх застосовують банки — обов’язкові поля, контрольні суми IBAN, структура BIC, контрольні підсумки
  • ✓Згенеруйте робочий файл pain.001.001.09 кредитового переказу, який можна переглянути, скопіювати або завантажити
  • ✓Підтвердьте результат за офіційною схемою ISO 20022 — справжня XSD, перевірена у вашому браузері

Важлива інформація

  • Жодні дані не завантажуються на сервер. Ваш файл читає лише ваш власний браузер, і він ніколи не залишає ваш комп’ютер — немає ні сервера, ні збереження, ні телеметрії. Це безпечно навіть для реальних даних, хоча знеособлені тестові дані — завжди добра практика.
  • Лише інструмент для тестування. Файли ніколи не передаються на обробку, і жодні ваші дії тут не можуть спричинити платіж.
  • Очікувані колонки: payment_id, payment_amount, currency, найменування платника та отримувача / IBAN / BIC, requested_execution_date — роздільники «кома», «крапка з комою» та табуляція визначаються автоматично. Завантажте зразок нижче та використайте його як шаблон для власного експорту.
  • Жодної плати. Цей інструмент і повний інструментарій, на якому він побудований, безкоштовні й мають відкритий вихідний код.

Переконайтеся самі

«Жодні дані не завантажуються» — це твердження, яке ви можете спростувати за дві хвилини:

  1. Відкрийте DevTools → Network і скористайтеся демонстрацією. Єдині запити — це GET-запити в межах цього самого домену для ресурсів сторінки, рушія WASM та схеми — жоден із них не передає ваших даних.
  2. Запустіть перевірку XSD один раз, а потім перемкніть DevTools у режим Offline (або вимкніть Wi-Fi). Уся демонстрація — включно з перевіркою за офіційною схемою — працює й далі: service worker кешує все після першого використання.
  3. Ця сторінка теж має відкритий код — логіка демонстрації міститься в одному модулі без залежностей, який можна прочитати повністю.

Тут немає ані скрипту аналітики, ані сервісу звітування про помилки, ані сторонніх шрифтів, ані кінцевої точки для звітів CSP — адже саме звітування вже було б вихідним з’єднанням.

3

Підтвердьте результат за офіційною XSD ISO 20022

Кроки 1–2 виконують швидкі перевірки, написані вручну. Цей крок запускає справжній механізм: середовище Python (через WebAssembly), яке виконує xmlschema за офіційною схемою pain.001.001.09 — той самий клас валідації, що його здійснює CLI. Рушій обсягом ~13 МБ надається з цього сайту й завантажується один раз — тоді, коли ви його запитаєте (він починає тихо завантажуватися, щойно крок 2 створює коректний XML).

Спершу згенеруйте XML на кроці 2 — перевірка XSD валідує саме цей результат.

    Усе на цій сторінці працює у вашому браузері — жодні дані не завантажуються, не зберігаються й нікуди не надсилаються. Ця демонстрація реалізує частину конвеєра (обов’язкові поля, IBAN mod-97, структура BIC, формати сум і дат, перераховані NbOfTxs/CtrlSum контрольні підсумки). Крок 3 запускає офіційну перевірку XSD просто тут, через WebAssembly. Встановлений інструментарій додає до цього валідацію за JSON Schema та п’ять наборів правил схем — встановіть CLI, щоб отримати повний конвеєр.

    Що показує ця демонстрація — і що додає справжній конвеєр

    Кожен зразковий пакет також можна завантажити як файл CSV і використати як шаблон для експорту з вашої ERP чи електронної таблиці — рядок заголовків і є контрактом.

    Демонстрація вище реалізує рівень fail-fast конвеєра Pain001: перевірки обов’язкових полів, контрольні суми IBAN mod-97 за ISO 13616, структуру BIC за ISO 9362, формати сум і дат, а також контрольні підсумки (NbOfTxs, CtrlSum), перераховані із записів, а не взяті на віру. Спробуйте меню «Додати помилку…» — кожен сценарій вносить рівно один реалістичний недолік (змінену цифру IBAN, некоректний BIC, відсутню колонку, суму з європейською десятковою комою, неможливу дату) і показує вам знахідку на рівні рядка, про яку шлюз банку інакше повідомив би лише через кілька днів.

    Встановлений інструментарій виконує значно глибшу перевірку: валідацію кожного запису за JSON Schema з нормалізацією псевдонімів полів, п’ять наборів правил схем (SEPA SCT, Instant, SDD Core, B2B, транскордонні) з виводом --explain за кожним правилом, а також фінальну валідацію сформованого документа за офіційною XSD ISO 20022, перш ніж буде записано хоч один байт. Десять версій pain.001 та pain.008.001.02 підтримуються.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Крок 3 вище — не симуляція: він запускає середовище Python у WebAssembly і виконує xmlschema за офіційною схемою pain.001.001.09, що надається з цього сайту — той самий клас перевірки XSD, який застосовує CLI. Лише в CLI залишається решта конвеєра: нормалізація за JSON Schema, п’ять наборів правил схем із --explain, а також десять інших визначень повідомлень.
