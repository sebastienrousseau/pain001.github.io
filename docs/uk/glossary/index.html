Глосарій платежів ISO 20022 простою мовою

Платіжна лексика простою мовою — для тих, хто підписує файли, а не лише для тих, хто їх генерує.

Прості визначення термінів, що трапляються на цьому сайті та в канальній документації вашого банку. Написано насамперед для казначеїв та операційних команд, а вже потім для інженерів.

Повідомлення#

pain.001 — Customer Credit Transfer Initiation. XML-повідомлення, яке клієнт надсилає своєму банку, щоб доручити один або кілька кредитових переказів. Родина "pain" означає payment initiation; .001 — номер повідомлення; кінцева версія (.001.09) фіксує схему.

pain.002 — Customer Payment Status Report. Відповідь банку на ваш pain.001 чи pain.008: прийнято, прийнято частково або відхилено, з кодами причин ISO за кожною транзакцією.

pain.008 — Customer Direct Debit Initiation. Близнюк pain.001 з боку стягнення: ви списуєте належні вам кошти за мандатом, а не надсилаєте гроші.

pacs.008 / pacs.009. Міжбанківські розрахункові повідомлення, на які перетворюється ваша інструкція після прийняття банком. Корпорації їх ніколи не складають; ними обмінюються банки.

camt.052 / camt.053 / camt.054. Звітність за рахунками: внутрішньоденний звіт, виписка на кінець дня та повідомлення про дебет/кредит відповідно. camt.053 — те, що команди звірки читають щоранку.

MT101. Застаріле текстове повідомлення SWIFT "Request for Transfer", на зміну якому приходить pain.001. Міжбанківську ретрансляцію MT101 виводять з експлуатації 14 листопада 2026 року на користь pain.001.001.09; MT101 від корпорації до банку зберігається лише на розсуд кожного банку.

Схеми та збірники правил#

SEPA SCT / SCT Inst. Євросхеми кредитових переказів (стандартна та миттєва), керовані збірниками правил Європейської платіжної ради. Миттєві перекази розраховуються за секунди, цілодобово.

SEPA SDD Core / B2B. Євросхеми прямого дебету — Core для споживачів (з правом повернення), B2B для бізнесу (без права повернення, суворіші перевірки мандатів).

CBPR+. Cross-Border Payments and Reporting Plus: настанови з використання, що профілюють повідомлення ISO 20022 для кореспондентського банкінгу SWIFT. Коли кажуть "міграція SWIFT на ISO 20022", мають на увазі CBPR+.

HVPS+. Аналогічне профілювання для систем великих платежів (T2, CHAPS, Fedwire та подібних).

CGI-MP. Common Global Implementation — Market Practice: група, що гармонізує використання корпораціями повідомлень pain у різних банках, щоб один формат файлу підходив багатьом банківським партнерам.

Verification of Payee (VoP). Обов'язкова в ЄС перевірка відповідності імені та IBAN, застосовувана до всіх кредитових переказів SEPA з 9 жовтня 2025 року. Виконується PSP у момент виконання; збіг визначають чисті дані про кредитора.

Ідентифікатори та дані#

IBAN. Міжнародний номер банківського рахунку (ISO 13616), самоперевірний через контрольну суму mod-97 — тому одна переставлена цифра виявляється до подання.

BIC / BICFI. Ідентифікаційний код фінансової установи за ISO 9362. XML-елемент називається <BIC> у pain.001.001.03, але <BICFI> починаючи з версії 9 — перейменування, що спричиняє реальні відхилення під час оновлення версій.

LEI. Legal Entity Identifier (ISO 17442) — глобальний 20-символьний ідентифікатор компанії. Активних понад 3 мільйони, і регулятори дедалі частіше вимагають їх у платежах.

UETR. Unique End-to-end Transaction Reference — UUID, що дає змогу відстежити платіж уздовж усього кореспондентського ланцюжка (SWIFT gpi).

Структурована / гібридна адреса. Поштові адреси як окремі XML-елементи (вулиця, місто, індекс, країна) проти рядків вільного тексту. З 14 листопада 2026 року CBPR+ відхиляє повністю неструктуровані адреси; гібрид — структуровані місто та країна плюс до двох адресних рядків по 70 символів — залишається чинним.

NbOfTxs / CtrlSum. Контрольні підсумки заголовка групи: кількість транзакцій і сума. Банки переобчислюють їх; якщо ваші розходяться, файл повертається. Pain001 завжди виводить їх із перевірених записів.

Платник комісії. Хто сплачує комісії: DEBT (відправник), CRED (отримувач), SHAR (порівну), SLEV (за правилами схеми). Застарілі MT-коди OUR/BEN/SHA відповідають першим трьом.

Призначення платежу (remittance information). Поле "за що цей платіж" — вільний текст (140 символів) або структуровані посилання. Те, що команди звірки мріють бачити заповненим як слід.

Інструментальні терміни на цьому сайті#

Валідація за XSD. Перевірка XML за офіційним визначенням схеми ISO 20022. Pain001 вважає її обов'язковим шлюзом перед записом будь-якого файлу.

MCP — Model Context Protocol. Відкритий стандарт, через який AI-асистенти викликають зовнішні інструменти. pain001-mcp надає 17 платіжних інструментів будь-якому MCP-клієнту, локально через stdio.

LSP — Language Server Protocol. Стандарт інтеграції з редакторами, що стоїть за діагностикою IDE. pain001-lsp використовує його, щоб перевіряти платіжні файли, поки ви друкуєте.

SBOM. Software Bill of Materials — машиночитний перелік усіх залежностей релізу, що генерується у форматі CycloneDX для релізів ядра Pain001.
