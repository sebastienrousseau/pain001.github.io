Demo interattiva

Provi Pain001 nel suo browser

Trascini un file CSV, utilizzi l’esempio o incolli i suoi record — la validazione viene eseguita all’istante, interamente nel suo browser, e nulla lascia mai il suo computer.

Come questo validatore la aiuta

  • ✓Verifichi i dati di pagamento con i controlli applicati dalle banche — campi obbligatori, checksum IBAN, struttura BIC, totali di controllo
  • ✓Generi un file di bonifico pain.001.001.09 funzionante da esaminare, copiare o scaricare
  • ✓Convalidi il risultato rispetto allo schema ufficiale ISO 20022 — l’autentico XSD, validato nel suo browser

Informazioni importanti

  • Nulla viene caricato. Il suo file viene letto dal suo browser e non lascia mai il suo computer — nessun server, nessuna archiviazione, nessuna telemetria. Sicuro anche con dati reali, benché usare dati di test mascherati resti una buona pratica.
  • Solo uno strumento di test. I file non vengono mai inviati per l’elaborazione e nulla di ciò che fa qui può dare origine a pagamenti.
  • Colonne attese: payment_id, payment_amount, currency, nome / IBAN / BIC di debitore e creditore, requested_execution_date — i delimitatori virgola, punto e virgola e tabulazione vengono rilevati automaticamente. Scarichi un esempio qui sotto da usare come modello per la sua esportazione.
  • Nessun costo. Questo strumento, e la toolchain completa che lo sostiene, sono gratuiti e open source.

Lo verifichi di persona

«Nulla viene caricato» è un’affermazione che può verificare in due minuti:

  1. Apra i DevTools → Rete, quindi utilizzi la demo. Le uniche richieste sono GET verso la stessa origine per le risorse di questa pagina, il motore WASM e lo schema — nessuna trasporta i suoi dati.
  2. Esegua una volta la validazione XSD, poi imposti i DevTools su Offline (o disattivi il Wi-Fi). L’intera demo — inclusa la validazione con lo schema ufficiale — continua a funzionare: un service worker memorizza tutto nella cache dopo il primo utilizzo.
  3. Anche questa pagina è open source — la logica della demo è un unico modulo privo di dipendenze che può leggere integralmente.

Non ci sono script di analisi, servizi di segnalazione errori, font di terze parti né endpoint di report CSP — la segnalazione stessa sarebbe una connessione in uscita.

    Che cosa mostra questa demo — e che cosa aggiunge la pipeline reale

    Ogni lotto di esempio è anche scaricabile come file CSV da usare come modello per l’esportazione dal suo ERP o foglio di calcolo — la riga di intestazione è il contratto.

    La demo qui sopra implementa il livello fail-fast della pipeline Pain001: controlli sui campi obbligatori, checksum IBAN mod-97 secondo ISO 13616, struttura BIC secondo ISO 9362, formati di importo e data, e totali di controllo (NbOfTxs, CtrlSum) ricalcolati dai record anziché dati per buoni. Provi il menu «Introduci un errore…» — ogni scenario inserisce esattamente un difetto realistico (una cifra IBAN invertita, un BIC malformato, una colonna mancante, un importo europeo con virgola decimale, una data impossibile) e le mostra l’esito a livello di riga che il gateway di una banca segnalerebbe altrimenti solo giorni dopo.

    La toolchain installata esegue un controllo molto più approfondito: validazione JSON Schema per ogni record con normalizzazione degli alias di campo, cinque insiemi di regole di schema (SEPA SCT, Instant, SDD Core, B2B, cross-border) con output --explain regola per regola, e validazione finale del documento generato rispetto all’XSD ufficiale ISO 20022 prima che un singolo byte venga scritto. Sono supportate dieci versioni di pain.001 e pain.008.001.02.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Il passaggio 3 qui sopra non è una simulazione: avvia un runtime Python in WebAssembly ed esegue xmlschema rispetto allo schema ufficiale pain.001.001.09, servito da questo sito — la stessa classe di controllo XSD applicata dalla CLI. Ciò che resta esclusivo della CLI è il resto della pipeline: la normalizzazione JSON Schema, i cinque insiemi di regole con --explain, e le altre dieci definizioni di messaggio.
