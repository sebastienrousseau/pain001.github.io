הדגמה אינטראקטיבית

נסו את Pain001 בדפדפן שלכם

גררו קובץ CSV, השתמשו בדוגמה או הדביקו רשומות משלכם — האימות רץ מיידית, כולו בדפדפן שלכם, ושום דבר לעולם אינו עוזב את המחשב שלכם.

כיצד המאמת הזה מסייע לכם

  • ✓בדקו נתוני תשלומים מול הבדיקות שהבנקים מפעילים — שדות חובה, ספרות ביקורת IBAN, מבנה BIC, סכומי בקרה
  • ✓הפיקו קובץ העברת זיכוי pain.001.001.09 תקין שתוכלו לבחון, להעתיק או להוריד
  • ✓הוכיחו את התוצאה מול הסכמה הרשמית של ISO 20022 — קובץ ה-XSD המקורי, מאומת בדפדפן שלכם

מידע חשוב

  • שום דבר אינו מועלה. הקובץ שלכם נקרא על ידי הדפדפן שלכם בלבד ולעולם אינו עוזב את המחשב — אין שרת, אין אחסון, אין טלמטריה. בטוח לנתונים אמיתיים, אם כי נתוני בדיקה ממוסכים הם תמיד נוהג טוב.
  • כלי בדיקה בלבד. קבצים לעולם אינם נשלחים לעיבוד ושום תשלום אינו יכול לנבוע ממה שתעשו כאן.
  • עמודות צפויות: payment_id, payment_amount, currency, שם החייב והזכאי / IBAN / BIC, requested_execution_date — מפרידי פסיק, נקודה-פסיק וטאב מזוהים אוטומטית. הורידו דוגמה למטה לשימוש כתבנית לייצוא משלכם.
  • ללא תשלום. הכלי הזה, ומערך הכלים המלא שמאחוריו, חינמיים ובקוד פתוח.

אמתו זאת בעצמכם

"שום דבר אינו מועלה" היא טענה שתוכלו להפריך בתוך שתי דקות:

  1. פתחו DevTools → Network והשתמשו בהדגמה. הבקשות היחידות הן בקשות GET מאותו מקור לנכסי העמוד, למנוע ה-WASM ולסכמה — אף אחת מהן אינה נושאת את הנתונים שלכם.
  2. הריצו את שער ה-XSD פעם אחת, ואז העבירו את DevTools למצב Offline (או כבו את ה-Wi-Fi). ההדגמה כולה — כולל שער הסכמה הרשמי — עדיין עובדת: service worker שומר הכול במטמון לאחר השימוש הראשון.
  3. גם העמוד הזה בקוד פתוח — לוגיקת ההדגמה היא מודול יחיד ללא תלויות שתוכלו לקרוא במלואו.

אין סקריפט אנליטיקה, אין שירות דיווח שגיאות, אין גופן של צד שלישי ואין נקודת קצה לדיווחי CSP — דיווח כזה היה בעצמו חיבור יוצא.

הוכיחו זאת מול ה-XSD הרשמי של ISO 20022

שלבים 1–2 מריצים בדיקות מהירות שנכתבו ידנית. השלב הזה מריץ את הדבר האמיתי: סביבת ריצה של Python (באמצעות WebAssembly) המריצה xmlschema מול סכמת pain.001.001.09 הרשמית — אותה מחלקת אימות שה-CLI מבצע. המנוע בנפח של כ-13 MB מוגש מהאתר הזה ומורד פעם אחת בלבד, כשתבקשו זאת (הוא מתחיל לרדת בשקט ברגע ששלב 2 מפיק XML תקין).

הפיקו XML בשלב 2 תחילה — שער ה-XSD מאמת את הפלט הזה.

    כל מה שבעמוד הזה רץ בדפדפן שלכם — שום דבר אינו מועלה, נשמר או נשלח לשום מקום. ההדגמה הזו מממשת תת-קבוצה של הצינור (שדות חובה, IBAN mod-97, מבנה BIC, פורמטים של סכום ותאריך, סכומי בקרה NbOfTxs/CtrlSum מחושבים מחדש). שלב 3 מריץ את שער ה-XSD הרשמי ממש כאן באמצעות WebAssembly. מערך הכלים המותקן מוסיף על כך אימות JSON Schema וחמישה ספרי כללים — התקינו את ה-CLI לצינור המלא.

    מה ההדגמה הזו מציגה — ומה הצינור האמיתי מוסיף

    כל אצוות דוגמה ניתנת גם להורדה כקובץ CSV לשימוש כתבנית לייצוא מ-ERP או מגיליון אלקטרוני משלכם — שורת הכותרת היא החוזה.

    ההדגמה שלמעלה מממשת את שכבת ה-fail-fast של צינור Pain001: בדיקות שדות חובה, ספרות ביקורת IBAN לפי ISO 13616 mod-97, מבנה BIC לפי ISO 9362, פורמטים של סכום ותאריך, וסכומי בקרה (NbOfTxs, CtrlSum) המחושבים מחדש מהרשומות במקום להסתמך עליהם. נסו את תפריט "הכניסו שגיאה…" — כל תרחיש שותל בדיוק פגם מציאותי אחד (ספרת IBAN הפוכה, BIC פגום, עמודה חסרה, סכום עם פסיק עשרוני אירופי, תאריך בלתי אפשרי) ומציג לכם את הממצא ברמת השורה ששער הבנק היה מדווח עליו אחרת רק כעבור ימים.

    מערך הכלים המותקן מריץ שער עמוק בהרבה: אימות JSON Schema לכל רשומה עם נרמול כינויי שדות, חמישה ספרי כללים (SEPA SCT, Instant, SDD Core, B2B, חוצה גבולות) עם פלט --explain כלל אחר כלל, ואימות סופי של המסמך המופק מול ה-XSD הרשמי של ISO 20022 לפני שנכתב ולו בית אחד. נתמכות עשר גרסאות pain.001 וכן pain.008.001.02.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    שלב 3 שלמעלה אינו סימולציה: הוא מאתחל סביבת ריצה של Python ב-WebAssembly ומריץ xmlschema מול סכמת pain.001.001.09 הרשמית, המוגשת מהאתר הזה — אותה מחלקת שער XSD שה-CLI מפעיל. מה שנותר בלעדי ל-CLI הוא שאר הצינור: נרמול JSON Schema, חמשת ספרי הכללים עם --explain, ועשר הגדרות ההודעות הנוספות.
