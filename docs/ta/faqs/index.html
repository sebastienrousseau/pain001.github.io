கருவூல அதிகாரிகள், பணப்பரிவர்த்தனைச் செயல்பாட்டாளர்கள், பொறியாளர்கள், தணிக்கையாளர்களுக்கான நேரடியான பதில்கள் — மக்கள் உண்மையில் கேட்கும் விதத்திலேயே.

பொருளடக்கம்

  1. கருவூல மற்றும் நிதித் தலைவர்களுக்கு
  2. பணப்பரிவர்த்தனைச் செயல்பாடுகளுக்கு
  3. பொறியாளர்கள் மற்றும் கட்டமைப்பாளர்களுக்கு
  4. தணிக்கையாளர்கள் மற்றும் இணக்கத்திற்கு

கருவூல அதிகாரிகள், பணப்பரிவர்த்தனைச் செயல்பாட்டாளர்கள், பொறியாளர்கள், தணிக்கையாளர்களுக்கான நேரடியான பதில்கள். மக்கள் உண்மையில் கேட்கும் விதத்திலேயே கேள்விகள் அமைக்கப்பட்டுள்ளன. ஆழமான தொழில்நுட்ப விவரங்களுக்கு தொழில்நுட்பக் குறிப்பைக் காண்க.

கருவூல மற்றும் நிதித் தலைவர்களுக்கு#

ஒரே பத்தியில் pain.001 என்றால் என்ன?

pain.001 என்பது வரவு பரிமாற்றங்களைத் தொடங்க ஒரு வாடிக்கையாளர் தனது வங்கிக்கு அனுப்பும் ISO 20022 செய்தி — SWIFT MT101 மற்றும் உள்நாட்டு ஃபிளாட் கோப்புகள் போன்ற வடிவங்களுக்கான XML வாரிசு. உங்கள் வங்கி அதை ஏற்பதற்கு முன் ஒரு ஸ்கீமாவுக்கும் ஒரு திட்ட விதிநூலுக்கும் எதிராகச் சரிபார்க்கிறது. Pain001 (மென்பொருள்) உங்களிடம் ஏற்கெனவே உள்ள தரவிலிருந்தே அந்தக் கோப்புகளை உருவாக்கி, நீங்கள் சமர்ப்பிப்பதற்கு முன்பே அவை செல்லுபடியாகும் என நிரூபிக்கிறது.

pain.001-க்கும் pain.008-க்கும் உள்ள வேறுபாடு என்ன?

பணம் நகரும் திசைதான். pain.001 வரவு பரிமாற்றங்களைத் தொடங்குகிறது — நீங்கள் பணத்தை வெளியே அனுப்புகிறீர்கள். pain.008 நேரடிப் பற்றுகளைத் தொடங்குகிறது — ஓர் ஆணையின் கீழ் உங்களுக்குச் சேர வேண்டிய பணத்தை நீங்கள் வசூலிக்கிறீர்கள். Pain001 இரண்டையும் உருவாக்குகிறது: pain.001-ன் பத்து பதிப்புகள் (.001.03 முதல் .001.12 வரை) மற்றும் pain.008.001.02.

நாங்கள் இன்னும் MT101 கோப்புகளையே அனுப்புகிறோம். இடம்பெயர்வு எவ்வளவு அவசரம்?

அவசரம்தான். எல்லை கடந்த வங்கிகளுக்கிடையிலான பணப்பரிவர்த்தனை அறிவுறுத்தல்களுக்கான MT வகை 1, 2, 9 செய்திகளை SWIFT நவம்பர் 2025-இல் நிறுத்தியது; இன்னும் MT-ஐ ஏற்கும் நிறுவனச் சேனல்கள் ஒவ்வொரு வங்கியின் விருப்பப்படியும், கடன் வாங்கிய காலத்திலுமே அவ்வாறு செய்கின்றன. MT101 லோடர் எதையும் மீண்டும் தட்டச்சு செய்யாமல், தற்போதைய MT101 ஓட்டங்களைச் சரிபார்க்கப்பட்ட pain.001 ஆக மாற்றுகிறது.

நவம்பர் 2026 கட்டமைக்கப்பட்ட முகவரி காலக்கெடு எங்களுக்கு என்ன பொருள்?

நவம்பர் 2026 இறுதி முதல், CBPR+ எல்லை கடந்த பணப்பரிவர்த்தனைகளில் முற்றிலும் கட்டமைக்கப்படாத அஞ்சல் முகவரிகள் ஏற்கப்பட மாட்டா; முகவரிகள் கட்டமைக்கப்பட்டதாகவோ கலப்பாகவோ இருக்க வேண்டும் — சுதந்திரப் பாட வரிகளுக்குப் பதிலாக ஊர் (), நாடு () போன்ற தனித்தனிக் கூறுகள். உங்கள் முதன்மைத் தரவில் முகவரிகள் ஒற்றைக் கட்டியாகச் சேமிக்கப்பட்டிருந்தால், வேலை உங்கள் தரவிலேயே உள்ளது, வங்கி இணைப்பில் அல்ல. அங்கிருந்தே தொடங்குங்கள். 2026 சுருக்கக் குறிப்பு காலவரிசையை விரிவாக விளக்குகிறது.

Pain001-ன் விலை என்ன?

எதுவும் இல்லை. மையப் பொதி Apache-2.0 / MIT என இரட்டை உரிமத்தில் உள்ளது; துணைப் பொதிகள் Apache-2.0. வணிகப் பயன்பாடு, மாற்றம், மறுவிநியோகம் அனைத்தும் அனுமதிக்கப்பட்டுள்ளன. அளவைப் புரிந்துகொள்ள: SWIFT-ன் மொழிபெயர்ப்பு SDK மட்டுமே ஆண்டுக்கு €10,000–30,000 என விலையிடப்பட்டுள்ளது.

பணப்பரிவர்த்தனைச் செயல்பாடுகளுக்கு#

வங்கிகள் ஏன் பணப்பரிவர்த்தனைக் கோப்புகளை நிராகரிக்கின்றன?

மீண்டும் மீண்டும் வரும் நான்கு காரணங்கள்: ஸ்கீமா மீறல்கள் (தவறான கூறு, தவறான பதிப்பு, தவறான பெயர்வெளி), தவறான அடையாளங்காட்டிகள் (IBAN செக்சம் தோல்விகள், தவறான வடிவிலான BIC-கள்), முறிந்த கட்டுப்பாட்டு மொத்தங்கள் (NbOfTxs / CtrlSum பரிவர்த்தனைகளுடன் பொருந்தாமை), மற்றும் ISO 20022 லத்தீன் தொகுப்புக்கு வெளியே உள்ள எழுத்துகள். கோப்பு உருவாகும் முன்பே Pain001 நான்கையும் சோதிக்கிறது: ஒவ்வொரு பதிவுக்கும் JSON Schema சரிபார்ப்பு, mod-97 IBAN மற்றும் ISO 9362 BIC சோதனைகள், மறுகணக்கிடப்பட்ட கட்டுப்பாட்டு மொத்தங்கள், எழுத்துத் தொகுப்பு ஒலிபெயர்ப்பு, உருவாக்கப்பட்ட XML-ன் இறுதி XSD சரிபார்ப்பு.

எதையும் உருவாக்காமல் ஒரு கோப்பைச் சரிபார்க்க முடியுமா?

ஆம் — pain001 --dry-run (அல்லது validate துணைக்கட்டளை, அல்லது POST /api/v1/validate). வெளியேற்றக் குறியீடு 0 என்றால் செல்லுபடியாகும்; 1 என்றால் புல அளவிலான பிழைகளுடன் சரிபார்ப்பு தோல்வியடைந்தது. இதை CI-இலோ சமர்ப்பிப்புக்கு முந்தைய சரிபார்ப்புப் பட்டியலிலோ இணைத்துக் கொள்ளுங்கள்.

எந்த SEPA விதிநூல்கள் உள்ளடக்கப்பட்டுள்ளன?

ஐந்து திட்ட விதிநூல்கள் உள்ளமைந்தே வழங்கப்படுகின்றன: SEPA Credit Transfer (sepa-sct), SEPA Instant (sepa-inst), SEPA Direct Debit Core (sepa-sdd), SEPA B2B (sepa-b2b), மற்றும் எல்லை கடந்த வரவு பரிமாற்றம் (xborder-ct). தேர்ச்சி பெற்ற அல்லது தோல்வியடைந்த ஒவ்வொரு விதியையும் காண --scheme --explain ஐப் பயன்படுத்துங்கள்.

எங்கள் தரவு Excel-இல் உள்ளது. சிக்கல் என்ன?

Excel, IBAN போன்ற சரங்களை அமைதியாக எண்களாக மாற்றிவிடும். Excel லோடர் .xlsx/.xlsm கோப்புகளை நேரடியாகப் படிக்கிறது; IBAN நெடுவரிசைகளில் எண் வடிவ கலங்கள் இருந்தால் உடனே நிறுத்திவிடுகிறது — சிதைவு வங்கியில் அல்ல, ஏற்றும் நேரத்திலேயே பிடிபடுகிறது.

500,000 வரிசைத் தொகுதியை இது எப்படிக் கையாளுகிறது?

--streaming உள்ளீட்டை நினைவக-வரம்புடைய துண்டுகளாகச் செயலாக்குகிறது (இயல்புநிலை 1,000 பரிவர்த்தனைகள்); ஒவ்வொரு துண்டும் சரியாக மறுகணக்கிடப்பட்ட கட்டுப்பாட்டு மொத்தங்களுடன் தனித் XML கோப்பாக வெளியிடப்படுகிறது. இதே காரணத்திற்காகவே REST API பணி நிலை வினவலுடன் POST /api/v1/generate/async ஐ வழங்குகிறது.

பொறியாளர்கள் மற்றும் கட்டமைப்பாளர்களுக்கு#

இதை எப்படி ஒருங்கிணைப்பது — நூலகமா, CLI-யா, API-யா?

மூன்றுமே முதல்-தர இடைமுகங்களாக உள்ளன: வகைக்குறிப்புள்ள Python API, CI-நட்பான வெளியேற்றக் குறியீடுகளுடன் கூடிய CLI, மேலும் ஒத்திசைவு, ஒத்திசைவற்ற பணி, இயங்குநிலை, Prometheus அளவீட்டு எண்ட்பாயிண்ட்களுடன் கூடிய FastAPI நுண்சேவை (pain001 serve). அடித்தளத்தில் ஒரே சரிபார்ப்புத் தொடர்வரிசைதான்; எனவே இடைமுகங்களுக்கு இடையே முடிவுகள் ஒருபோதும் வேறுபடுவதில்லை.

XML உருவாக்கம் ஃப்ளோட் வட்டமிடலிலிருந்து உண்மையிலேயே பாதுகாப்பானதா?

உருவாக்கத்திலும் திட்டச் சரிபார்ப்பிலும் தொகைகள் முழுவதுமாக decimal.Decimal ஆகவே இருக்கின்றன — துல்லியமான தசமங்களாகப் பாகுபடுத்தப்பட்டு, துல்லியமான தசமங்களாகக் கூட்டப்பட்டு, ஃப்ளோட் வடிவமின்றி வெளியிடப்படுகின்றன. கட்டுப்பாட்டு மொத்தங்கள் சரிபார்க்கப்பட்ட பதிவுகளிலிருந்து மறுகணக்கிடப்படுகின்றன; உள்ளீடு ஒருபோதும் நம்பப்படுவதில்லை.

பாதுகாப்பு நிலை எப்படி உள்ளது?

அனைத்து XML பாகுபடுத்தலும் defusedxml வழியாகவே செல்கிறது (XXE மற்றும் entity-expansion தாக்குதல்களைத் தடுக்கிறது); சார்புமரத்தில் lxml இல்லவே இல்லை. உள்ளீடுகள் ஒரு பாதை-ஊடுருவல் சரிபார்ப்பானைக் கடக்கின்றன. Docker படிமம் ரூட் அல்லாத பயனராக இயங்குகிறது. மைய வெளியீடுகளுக்கு ஒரு CycloneDX SBOM உருவாக்கப்படுகிறது; PAIN001_DISABLE_PLUGINS=1 மூலம் மூன்றாம் தரப்புச் செருகுநிரல் கண்டறிதலை முற்றிலுமாக முடக்கலாம்.

தரம் எவ்வாறு உறுதி செய்யப்படுகிறது?

மையப் பொதியில் கடும் CI நுழைவாயிலாக 100% வரி மற்றும் கிளை கவரேஜ் (சரிபார்க்கத்தக்க வகையில்: 3,828 வரிகள், 926 கிளைகள் 100%-இல்), கடுமையான mypy, 100% டாக்ஸ்ட்ரிங் கவரேஜ், Bandit மற்றும் pip-audit பாதுகாப்பு லிண்டிங், CodeQL ஸ்கேனிங். துணைப் பொதிகளும் இதே 100% கவரேஜ் ஒழுங்கைப் பின்பற்றுகின்றன.

தனியுரிம வடிவம் ஒன்றுக்கு இதை விரிவாக்க முடியுமா?

ஆம் — நான்கு செருகுநிரல் நுழைவுப்புள்ளிக் குழுக்கள் (pain001.loaders, pain001.validators, pain001.schemes, pain001.writers). Excel லோடரே பொதுவான நெறிமுறையைப் பயன்படுத்தும் ஒரு செருகுநிரல்தான்; எனவே அது ஒரு முன்மாதிரி அமலாக்கமாகவும் அமைகிறது.

தணிக்கையாளர்கள் மற்றும் இணக்கத்திற்கு#

கடந்த காலாண்டில் உருவாக்கப்பட்ட கோப்பை மீண்டும் உருவாக்க முடியுமா?

ஆம். பொதியின் பதிப்பை நிலைநிறுத்தி, அதே உள்ளீட்டை மீண்டும் இயக்குங்கள் — வெளியீடு நிர்ணயமானது. கருவித்தொகுப்பு ஓப்பன் சோர்ஸ் என்பதால், தணிக்கைத் தடம் விற்பனையாளரின் உறுதிமொழியோடு நின்றுவிடாமல் நிரல் பாதை வரை நீள்கிறது.

பணப்பரிவர்த்தனைத் தரவு எங்கள் சூழலை விட்டு வெளியேறுகிறதா?

இல்லை. ஒவ்வொரு கூறும் — CLI, நூலகம், REST API, MCP சேவையகம், LSP — உள்ளூரிலேயே இயங்குகிறது. டெலிமெட்ரி இல்லை, SaaS கால்பேக் இல்லை, வெளிப்புறச் சரிபார்ப்புச் சேவை இல்லை. MCP சேவையகம் stdio வழியாக மட்டுமே தொடர்பு கொள்கிறது; அதன் 17 கருவிகளும் படிக்க-மட்டும் மற்றும் இடம்பெயராதவை எனக் குறிக்கப்பட்டுள்ளன.

Pain001-ஐ யார் பராமரிக்கிறார்கள்?

லண்டனை மையமாகக் கொண்ட ஃபின்டெக் பொறியியல் தலைவர் Sebastien Rousseau, சமூகப் பங்களிப்பாளர்களுடன் இணைந்து. உருவாக்கப் பணி GitHub-இல் பொதுவெளியில் நடைபெறுகிறது, வெளியீடுகள் PyPI-இல் வெளியிடப்படுகின்றன, ஒவ்வொரு வெளியீட்டுடனும் மாற்றப்பதிவு பதிப்பிடப்படுகிறது.

Pain001

திறந்த மூல ISO 20022 கட்டணத் தொடக்கம். சரிபார்க்கப்பட்ட கோப்புகள், உள்ளூர் செயலாக்கம், எந்தக் கட்டுப்பாடும் இல்லை.
