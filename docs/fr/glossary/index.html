Glossaire ISO 20022 des paiements, en français clair

Le vocabulaire des paiements en français clair — pour celles et ceux qui signent les fichiers, pas seulement pour ceux qui les génèrent.

3 min de lecture Dernière révision 2026-07-26

Sommaire

  1. Messages
  2. Schémas et recueils de règles
  3. Identifiants et données
  4. Termes d'outillage utilisés sur ce site

Des définitions en clair des termes qui apparaissent sur ce site et dans la documentation de canal de votre banque. Écrites d'abord pour les trésoriers et les équipes d'exploitation, ensuite pour les ingénieurs.

Messages#

pain.001 — Customer Credit Transfer Initiation. Le message XML qu'un client envoie à sa banque pour ordonner un ou plusieurs virements. La famille « pain » signifie payment initiation ; .001 est le numéro de message ; la version finale (.001.09) fixe le schéma.

pain.002 — Customer Payment Status Report. La réponse de la banque à votre pain.001 ou pain.008 : accepté, partiellement accepté ou rejeté, avec des codes motifs ISO par transaction.

pain.008 — Customer Direct Debit Initiation. Le jumeau côté encaissement de pain.001 : vous prélevez des fonds qui vous sont dus au titre d'un mandat au lieu de pousser des fonds vers l'extérieur.

pacs.008 / pacs.009. Les messages de règlement interbancaire que devient votre instruction une fois acceptée par la banque. Les entreprises ne les rédigent jamais ; les banques les échangent entre elles.

camt.052 / camt.053 / camt.054. Le reporting de compte : rapport intrajournalier, relevé de fin de journée et avis de débit/crédit, respectivement. camt.053 est ce que les équipes de rapprochement consomment chaque matin.

MT101. L'ancien message texte SWIFT « Request for Transfer » que pain.001 remplace. Le relais MT101 interbancaire est mis hors service le 14 novembre 2026 au profit de pain.001.001.09 ; le MT101 entreprise-banque ne subsiste qu'à la discrétion de chaque banque.

Schémas et recueils de règles#

SEPA SCT / SCT Inst. Les schémas de virement en euros (standard et instantané) régis par les recueils de règles du Conseil européen des paiements. Les virements instantanés se règlent en quelques secondes, en continu.

SEPA SDD Core / B2B. Les schémas de prélèvement en euros — Core pour les consommateurs (avec droit à remboursement), B2B pour les entreprises (sans droit à remboursement, contrôles de mandat plus stricts).

CBPR+. Cross-Border Payments and Reporting Plus : les lignes directrices d'usage qui profilent les messages ISO 20022 pour la banque de correspondance SWIFT. Quand on parle de « la migration ISO 20022 de SWIFT », il s'agit de CBPR+.

HVPS+. Le profilage équivalent pour les systèmes de paiement de montant élevé (T2, CHAPS, Fedwire et leurs pairs).

CGI-MP. Common Global Implementation — Market Practice : le groupe qui harmonise l'usage des messages pain par les entreprises à travers les banques, afin qu'un même format de fichier puisse servir de nombreux partenaires bancaires.

Verification of Payee (VoP). Le contrôle de concordance nom/IBAN imposé par l'UE, appliqué à tous les virements SEPA depuis le 9 octobre 2025. Effectué par le PSP au moment de l'exécution ; la propreté des données créancier détermine la concordance.

Identifiants et données#

IBAN. International Bank Account Number (ISO 13616), auto-vérifiable via une somme de contrôle mod-97 — raison pour laquelle un seul chiffre transposé est détectable avant soumission.

BIC / BICFI. Le Business Identifier Code ISO 9362 d'une institution financière. L'élément XML est dans pain.001.001.03 mais à partir de la version 9 — un renommage qui cause de vrais rejets lors des montées de version.

LEI. Legal Entity Identifier (ISO 17442) — l'identifiant mondial d'entreprise à 20 caractères. Plus de 3 millions sont actifs, et les régulateurs les imposent de plus en plus dans les paiements.

UETR. Unique End-to-end Transaction Reference — l'UUID qui permet de tracer un paiement à travers la chaîne de correspondance (SWIFT gpi).

Adresse structurée / hybride. Les adresses postales sous forme d'éléments XML discrets (rue, ville, code postal, pays) par opposition aux lignes en texte libre. À partir du 14 novembre 2026, CBPR+ rejette les adresses entièrement non structurées ; l'hybride — ville et pays structurés plus jusqu'à deux lignes d'adresse de 70 caractères — reste valide.

NbOfTxs / CtrlSum. Les totaux de contrôle de l'en-tête de groupe : nombre de transactions et somme des montants. Les banques les recalculent ; si les vôtres divergent, le fichier est rejeté. Pain001 les dérive toujours des enregistrements validés.

Charge bearer. Qui paie les frais : DEBT (émetteur), CRED (bénéficiaire), SHAR (partagés), SLEV (selon les règles du schéma). Les anciens codes MT OUR/BEN/SHA correspondent aux trois premiers.

Remittance information. Le champ « objet du paiement » — texte libre (140 caractères) ou références structurées. Ce que les équipes de rapprochement aimeraient voir correctement renseigné par tout le monde.

Termes d'outillage utilisés sur ce site#

Validation XSD. La vérification du XML contre la définition de schéma ISO 20022 officielle. Pain001 la traite comme une porte stricte avant l'écriture de tout fichier.

MCP — Model Context Protocol. Le standard ouvert par lequel les assistants IA appellent des outils externes. pain001-mcp expose 17 outils de paiement à tout client MCP, localement via stdio.

LSP — Language Server Protocol. Le standard d'intégration aux éditeurs derrière les diagnostics d'IDE. pain001-lsp l'utilise pour valider les fichiers de paiement au fil de la frappe.

SBOM. Software Bill of Materials — l'inventaire lisible par machine de chaque dépendance d'une release, généré au format CycloneDX pour les releases du cœur de Pain001.

Un terme manque ? Proposez-le — ce glossaire grandit avec les questions réellement posées.
