Try Pain001 in Your Browser

Drop in a CSV, use the sample, or paste your own records — validation runs instantly, entirely in your browser, and nothing ever leaves your machine.

How this validator helps you

  • ✓Test payment data against the checks banks apply — required fields, IBAN checksums, BIC structure, control totals
  • ✓Generate a working pain.001.001.09 credit-transfer file you can inspect, copy, or download
  • ✓Prove the result against the official ISO 20022 schema — the genuine XSD, validated in your browser

Important information

  • Nothing is uploaded. Your file is read by your own browser and never leaves your machine — there is no server, no storage, no telemetry. Safe for real data, though masked test data is always good practice.
  • Testing tool only. Files are never submitted for processing and no payments can result from anything you do here.
  • Expected columns: payment_id, payment_amount, currency, debtor and creditor name / IBAN / BIC, requested_execution_date — comma, semicolon, and tab delimiters are auto-detected. Download a sample below to use as a template for your own export.
  • No charges. This tool, and the full toolchain behind it, are free and open source.

Verify it yourself

"Nothing is uploaded" is a claim you can falsify in two minutes:

  1. Open DevTools → Network, then use the demo. The only requests are same-origin GETs for this page's assets, the WASM engine, and the schema — none carries your data.
  2. Run the XSD gate once, then switch DevTools to Offline (or turn off Wi-Fi). The whole demo — including the official schema gate — still works: a service worker caches everything after first use.
  3. This page is open source too — the demo logic is one dependency-free module you can read in full.

There is no analytics script, no error-reporting service, no third-party font, and no CSP report endpoint — reporting would itself be an outbound connection.

    What this demo shows — and what the real pipeline adds

    Each sample batch is also downloadable as a CSV file to use as the template for your own ERP or spreadsheet export — the header row is the contract.

    The demo above implements the fail-fast layer of the Pain001 pipeline: required-field checks, ISO 13616 mod-97 IBAN checksums, ISO 9362 BIC structure, amount and date formats, and control totals (NbOfTxs, CtrlSum) recomputed from the records rather than trusted. Try the "Introduce an error…" menu — each scenario plants exactly one realistic flaw (a flipped IBAN digit, a malformed BIC, a missing column, a European comma-decimal amount, an impossible date) and shows you the row-level finding a bank's gateway would otherwise report days later.

    The installed toolchain runs a much deeper gate: JSON Schema validation per record with field-alias normalisation, five scheme rulebooks (SEPA SCT, Instant, SDD Core, B2B, cross-border) with rule-by-rule --explain output, and final validation of the rendered document against the official ISO 20022 XSD before a single byte is written. Ten pain.001 versions and pain.008.001.02 are supported.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Step 3 above is not a simulation: it boots a Python runtime in WebAssembly and runs xmlschema against the official pain.001.001.09 schema, served from this site — the same class of XSD gate the CLI applies. What remains CLI-only is the rest of the pipeline: JSON Schema normalisation, the five scheme rulebooks with --explain, and the other ten message definitions.
