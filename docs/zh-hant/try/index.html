互動式示範

在瀏覽器中試用 Pain001

拖入 CSV 檔案、使用範例或貼上您自己的紀錄——驗證即時執行，完全在您的瀏覽器中進行，任何資料都不會離開您的裝置。

此驗證工具如何為您服務

  • ✓依照銀行所採用的檢查測試付款資料——必填欄位、IBAN 檢查碼、BIC 結構、控制總額
  • ✓產生一個可用的 pain.001.001.09 信用轉帳檔案，供您檢視、複製或下載
  • ✓依據官方 ISO 20022 Schema 驗證結果——貨真價實的 XSD，在您的瀏覽器中完成驗證

重要資訊

  • 不會上傳任何資料。您的檔案由您自己的瀏覽器讀取，絕不會離開您的裝置——沒有伺服器、沒有儲存、沒有遙測。可安全用於真實資料，但使用去識別化的測試資料始終是良好做法。
  • 僅為測試工具。檔案絕不會被送出處理，您在此進行的任何操作都不會產生任何付款。
  • 預期欄位： payment_id, payment_amount, currency, 付款人與受款人名稱 / IBAN / BIC, requested_execution_date ——逗號、分號與定位字元分隔皆可自動偵測。請在下方下載範例，作為您自己匯出檔案的範本。
  • 不收取任何費用。此工具及其背後的完整工具鏈皆為免費且開放原始碼。

親自驗證

「不會上傳任何資料」是一項您可以在兩分鐘內自行檢驗真偽的聲明：

  1. 開啟 DevTools → Network，然後使用本示範。僅有的請求是用於取得本頁資源、WASM 引擎與 Schema 的同源 GET 請求——沒有任何請求攜帶您的資料。
  2. 先執行一次 XSD 關卡，再將 DevTools 切換為離線模式（或關閉 Wi-Fi）。整個示範——包括官方 Schema 關卡——仍然可用：Service Worker 會在首次使用後快取所有內容。
  3. 本頁面同樣開放原始碼——示範邏輯是一個零相依模組，您可以完整閱讀其原始碼。

沒有分析指令碼、沒有錯誤回報服務、沒有第三方字型，也沒有 CSP 回報端點——回報本身就已是一次對外連線。

3

依據官方 ISO 20022 XSD 進行驗證

步驟 1–2 執行的是快速的手寫檢查。此步驟執行的則是貨真價實的驗證：一個 Python 執行環境（透過 WebAssembly）執行 xmlschema ，依據官方 pain.001.001.09 Schema 進行驗證—— 與 CLI 所執行的驗證屬於同一等級。約 13 MB 的引擎由本 網站提供，僅在您要求時下載一次（當步驟 2 產生有效 XML 後， 便會開始安靜下載）。

請先在步驟 2 產生 XML——XSD 關卡驗證的正是該輸出。

    本頁面的一切都在您的瀏覽器中執行——不會上傳、儲存或傳送任何資料到任何地方。 本示範實作了管線的一個子集（必填欄位、IBAN mod-97、BIC 結構、金額 與日期格式、重新計算的 NbOfTxs/CtrlSum 控制總額）。步驟 3 透過 WebAssembly 就地執行官方 XSD 關卡。安裝版工具鏈 在此之上還提供 JSON Schema 驗證與五套方案規則手冊—— 安裝 CLI 以取得完整管線。

    本示範展示的內容——以及真實管線的額外能力

    每個範例批次也可下載為 CSV 檔案，作為您自己 ERP 或試算表匯出的範本——標題列即是約定。

    上方示範實作的是 Pain001 管線的快速失敗層：必填欄位檢查、ISO 13616 mod-97 IBAN 檢查碼、ISO 9362 BIC 結構、金額與日期格式，以及從紀錄重新計算而非直接信任的控制總額 (NbOfTxs, CtrlSum)。試試「引入錯誤…」選單——每個情境都會植入恰好一個真實缺陷（IBAN 數字對調、BIC 格式錯誤、缺漏欄位、歐式逗號小數金額、不可能的日期），並向您展示銀行閘道原本要在數日後才會回報的列層級發現。

    安裝版工具鏈執行的關卡則深入得多：對每筆紀錄進行含欄位別名正規化的 JSON Schema 驗證、五套方案規則手冊（SEPA SCT、Instant、SDD Core、B2B、跨境）並逐條規則輸出 --explain，以及在寫出任何一個位元組之前依據官方 ISO 20022 XSD 對產出文件的最終驗證。支援十個 pain.001 版本及 pain.008.001.02。

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    上方步驟 3 並非模擬：它在 WebAssembly 中啟動一個 Python 執行環境，並依據由本網站提供的官方 pain.001.001.09 Schema 執行 xmlschema——與 CLI 套用的 XSD 關卡屬於同一等級。仍僅限 CLI 的是管線的其餘部分：JSON Schema 正規化、含 --explain 的五套方案規則手冊，以及其餘十種訊息定義。
