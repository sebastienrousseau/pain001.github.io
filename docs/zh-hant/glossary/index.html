ISO 20022 支付詞彙表（白話解釋）

白話的支付詞彙——寫給在檔案上簽核的人，而不只是產生檔案的人。

3 分鐘閱讀 最近審核 2026-07-26

目錄

  2. 方案與規則手冊

以白話定義本站與您銀行通道文件中出現的詞彙。優先寫給財資與營運團隊，其次才是工程師。

電文#

pain.001——客戶貸記轉帳發動（Customer Credit Transfer Initiation）。客戶傳送給銀行、用以指示一筆或多筆貸記轉帳的 XML 電文。「pain」家族代表付款發動（payment initiation）；.001 是電文編號；結尾的版本（.001.09）鎖定結構描述。

pain.002——客戶付款狀態報告（Customer Payment Status Report）。銀行對您的 pain.001 或 pain.008 的回覆：受理、部分受理或退回，並附每筆交易的 ISO 原因代碼。

pain.008——客戶直接扣款發動（Customer Direct Debit Initiation）。pain.001 的收款側雙生電文：您依扣款授權收取應收款項，而非把資金匯出。

pacs.008 / pacs.009。您的指示獲銀行受理後轉化成的銀行間清算電文。企業從不編製這些電文；它們由銀行彼此交換。

camt.052 / camt.053 / camt.054。帳戶報告：分別為日中報告、日終對帳單與借記/貸記通知。camt.053 就是對帳團隊每天早上處理的內容。

MT101。由 pain.001 取代的傳統 SWIFT「轉帳請求」文字電文。銀行間 MT101 轉發將於 2026 年 11 月 14 日除役，改用 pain.001.001.09；企業對銀行的 MT101 是否延續全憑各銀行決定。

方案與規則手冊#

SEPA SCT / SCT Inst。受歐洲支付理事會規則手冊規範的歐元貸記轉帳方案（標準與即時）。即時轉帳全年無休、數秒內完成清算。

SEPA SDD Core / B2B。歐元直接扣款方案——Core 供消費者使用（享退款權），B2B 供企業使用（無退款權，授權審查更嚴格）。

CBPR+。Cross-Border Payments and Reporting Plus（跨境支付與報告增強版）：為 SWIFT 通匯銀行業務裁適 ISO 20022 電文的使用指引。人們口中的「SWIFT ISO 20022 移轉」，指的就是 CBPR+。

HVPS+。大額支付系統（T2、CHAPS、Fedwire 等）的對應裁適規範。

CGI-MP。Common Global Implementation — Market Practice（共同全球實施——市場實務）：致力於統一企業跨銀行使用 pain 電文方式的組織，讓同一種檔案格式能服務多家往來銀行。

收款人驗證（Verification of Payee，VoP）。自 2025 年 10 月 9 日起適用於所有 SEPA 貸記轉帳的歐盟強制姓名/IBAN 比對檢查。由 PSP 於執行當下完成；收款人資料是否乾淨決定比對能否成功。

識別碼與資料#

IBAN。國際銀行帳戶號碼（ISO 13616），透過 mod-97 檢核碼自我檢查——因此即使只有一位數字對調，也能在提交之前被偵測出來。

BIC / BICFI。金融機構的 ISO 9362 商業識別碼。此 XML 元素在 pain.001.001.03 為 ，自版本 9 起改為 ——這項更名在版本升級時造成過實際退件。

LEI。法人機構識別碼（ISO 17442）——20 碼的全球企業識別碼。現有超過 300 萬個處於有效狀態，且監理機關日益要求在支付中使用。

UETR。端對端唯一交易參考碼（Unique End-to-end Transaction Reference）——讓一筆付款能沿通匯鏈全程追蹤的 UUID（SWIFT gpi）。

結構化 / 混合地址。以獨立 XML 元素（街道、城鎮、郵遞區號、國家）表示的郵政地址，相對於自由文字行。自 2026 年 11 月 14 日起，CBPR+ 拒收完全非結構化的地址；混合形式——結構化的城鎮與國家，加上最多兩行 70 字元的地址行——仍屬有效。

NbOfTxs / CtrlSum。群組標頭的控制總計：交易筆數與金額合計。銀行會重新計算；若您的數字對不上，檔案就會被退回。Pain001 一律由已驗證的記錄推導這兩個值。

費用負擔別。由誰負擔手續費：DEBT（付款人）、CRED（收款人）、SHAR（雙方分攤）、SLEV（依方案規則）。傳統 MT 的 OUR/BEN/SHA 對應前三者。

匯款資訊。說明「這筆款項所為何來」的欄位——自由文字（140 個字元）或結構化參考。也是對帳團隊最希望大家好好填寫的欄位。

本站使用的工具詞彙#

XSD 驗證。依官方 ISO 20022 結構描述定義檢查 XML。Pain001 將其視為寫出任何檔案前的硬性關卡。

MCP——模型上下文協定（Model Context Protocol）。AI 助理呼叫外部工具所依循的開放標準。pain001-mcp 透過本機 stdio 向任何 MCP 用戶端提供 17 個支付工具。

LSP——語言伺服器協定（Language Server Protocol）。支撐 IDE 診斷的編輯器整合標準。pain001-lsp 藉此在您輸入的同時驗證付款檔案。

SBOM。軟體物料清單（Software Bill of Materials）——機器可讀的發行相依清單，Pain001 核心發行版以 CycloneDX 格式產生。
