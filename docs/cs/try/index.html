Interaktivní demo

Vyzkoušejte Pain001 ve svém prohlížeči

Přetáhněte CSV, použijte ukázku nebo vložte vlastní záznamy — validace proběhne okamžitě, výhradně ve vašem prohlížeči, a nic nikdy neopustí váš počítač.

Jak vám tento validátor pomůže

  • ✓Otestujte platební data proti kontrolám, které uplatňují banky — povinná pole, kontrolní číslice IBAN, struktura BIC, kontrolní součty
  • ✓Vygenerujte funkční pain.001.001.09 soubor úhrady, který můžete prohlédnout, zkopírovat nebo stáhnout
  • ✓Ověřte výsledek proti oficiálnímu schématu ISO 20022 — pravé XSD, validované ve vašem prohlížeči

Důležité informace

  • Nic se nenahrává. Váš soubor čte pouze váš vlastní prohlížeč a nikdy neopustí váš počítač — neexistuje žádný server, žádné úložiště, žádná telemetrie. Bezpečné i pro reálná data, i když maskovaná testovací data jsou vždy dobrou praxí.
  • Pouze testovací nástroj. Soubory se nikdy neodesílají ke zpracování a nic, co zde uděláte, nemůže vést k platbě.
  • Očekávané sloupce: payment_id, payment_amount, currency, jméno / IBAN / BIC plátce a příjemce, requested_execution_date — oddělovače čárka, středník i tabulátor se rozpoznají automaticky. Níže si stáhněte ukázku jako šablonu pro vlastní export.
  • Žádné poplatky. Tento nástroj i celá sada nástrojů za ním jsou zdarma a open source.

Ověřte si to sami

"Nic se nenahrává" je tvrzení, které můžete za dvě minuty vyvrátit:

  1. Otevřete DevTools → Network a poté demo použijte. Jediné požadavky jsou same-origin GET pro prostředky této stránky, WASM engine a schéma — žádný z nich nenese vaše data.
  2. Spusťte XSD bránu jednou a poté přepněte DevTools do režimu Offline (nebo vypněte Wi-Fi). Celé demo — včetně oficiální schémové brány — funguje dál: service worker po prvním použití vše ukládá do mezipaměti.
  3. I tato stránka je open source — logika dema je jediný modul bez závislostí, který si můžete celý přečíst.

Není zde žádný analytický skript, žádná služba hlášení chyb, žádné písmo třetí strany ani žádný CSP report endpoint — samotné hlášení by bylo odchozím spojením.

3

Ověřte jej proti oficiálnímu XSD ISO 20022

Kroky 1–2 provádějí rychlé, ručně psané kontroly. Tento krok spouští originál: běhové prostředí Pythonu (přes WebAssembly) vykonávající xmlschema proti oficiálnímu pain.001.001.09 schématu — stejnou třídu validace, jakou provádí CLI. Engine o velikosti ~13 MB je servírován z tohoto webu a stahuje se jednou, když o něj požádáte (stahování začne tiše, jakmile krok 2 vytvoří platné XML).

Nejprve vygenerujte XML v kroku 2 — XSD brána validuje právě tento výstup.

    Vše na této stránce běží ve vašem prohlížeči — nic se nenahrává, neukládá ani nikam neodesílá. Toto demo implementuje podmnožinu pipeline (povinná pole, IBAN mod-97, struktura BIC, formáty částek a dat, přepočtené NbOfTxs/CtrlSum kontrolní součty). Krok 3 spouští oficiální XSD bránu přímo zde přes WebAssembly. Nainstalovaná sada nástrojů navíc přidává validaci JSON Schema a pět sad pravidel platebních schémat — nainstalujte CLI pro kompletní pipeline.

    Co toto demo ukazuje — a co přidává skutečná pipeline

    Každou ukázkovou dávku lze také stáhnout jako soubor CSV a použít jako šablonu pro export z vlastního ERP nebo tabulky — hlavičkový řádek je smlouvou.

    Demo výše implementuje vrstvu fail-fast pipeline Pain001: kontroly povinných polí, kontrolní číslice IBAN mod-97 dle ISO 13616, strukturu BIC dle ISO 9362, formáty částek a dat a kontrolní součty (NbOfTxs, CtrlSum) přepočítávané ze záznamů, nikoli slepě přebírané. Vyzkoušejte nabídku "Zavést chybu…" — každý scénář vloží přesně jednu realistickou vadu (prohozenou číslici IBAN, vadný BIC, chybějící sloupec, evropskou částku s desetinnou čárkou, nemožné datum) a ukáže vám zjištění na úrovni řádku, které by brána banky jinak ohlásila až o několik dní později.

    Nainstalovaná sada nástrojů provozuje mnohem hlubší bránu: validaci JSON Schema pro každý záznam s normalizací aliasů polí, pět sad pravidel platebních schémat (SEPA SCT, Instant, SDD Core, B2B, přeshraniční) s výstupem --explain pravidlo po pravidlu a závěrečnou validaci vykresleného dokumentu proti oficiálnímu XSD ISO 20022 dříve, než se zapíše jediný bajt. Podporováno je deset pain.001 verzí a pain.008.001.02.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    Krok 3 výše není simulace: spouští běhové prostředí Pythonu ve WebAssembly a vykonává xmlschema proti oficiálnímu pain.001.001.09 schématu servírovanému z tohoto webu — stejná třída XSD brány, jakou uplatňuje CLI. Pouze v CLI zůstává zbytek pipeline: normalizace JSON Schema, pět sad pravidel s --explain, a zbývajících deset definic zpráv.
