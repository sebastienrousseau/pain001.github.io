دموی تعاملی

Pain001 را در مرورگر خود امتحان کنید

یک فایل CSV رها کنید، از نمونه استفاده کنید یا رکوردهای خود را جای‌گذاری کنید — اعتبارسنجی بلافاصله و به‌طور کامل در مرورگر شما اجرا می‌شود و هیچ‌چیز هرگز از دستگاه شما خارج نمی‌شود.

این اعتبارسنج چگونه به شما کمک می‌کند

  • ✓داده‌های پرداخت را با همان بررسی‌هایی بیازمایید که بانک‌ها اعمال می‌کنند — فیلدهای الزامی، ارقام کنترلی IBAN، ساختار BIC، جمع‌های کنترلی
  • ✓یک فایل انتقال اعتبار pain.001.001.09 کارآمد بسازید که می‌توانید بررسی، کپی یا دانلود کنید
  • ✓نتیجه را با طرحواره رسمی ISO 20022 اثبات کنید — فایل XSD اصل، اعتبارسنجی‌شده در مرورگر شما

اطلاعات مهم

  • هیچ‌چیز بارگذاری نمی‌شود. فایل شما توسط مرورگر خودتان خوانده می‌شود و هرگز از دستگاه شما خارج نمی‌شود — نه سروری هست، نه ذخیره‌سازی و نه تله‌متری. برای داده‌های واقعی امن است، هرچند استفاده از داده‌های آزمایشی پوشیده همیشه رویه خوبی است.
  • صرفاً ابزار آزمایش. فایل‌ها هرگز برای پردازش ارسال نمی‌شوند و هیچ پرداختی از آنچه اینجا انجام می‌دهید ناشی نخواهد شد.
  • ستون‌های مورد انتظار: payment_id, payment_amount, currency, نام بدهکار و بستانکار / IBAN / BIC, requested_execution_date — جداکننده‌های ویرگول، نقطه‌ویرگول و تب به‌طور خودکار تشخیص داده می‌شوند. نمونه‌ای را در پایین دانلود کنید تا الگوی خروجی خودتان باشد.
  • بدون هزینه. این ابزار و زنجیره ابزار کامل پشت آن، رایگان و متن‌باز هستند.

خودتان راستی‌آزمایی کنید

«هیچ‌چیز بارگذاری نمی‌شود» ادعایی است که می‌توانید در دو دقیقه ابطال کنید:

  1. DevTools → Network را باز کنید و سپس از دمو استفاده کنید. تنها درخواست‌ها، درخواست‌های GET هم‌مبدأ برای دارایی‌های این صفحه، موتور WASM و طرحواره هستند — هیچ‌کدام داده شما را حمل نمی‌کنند.
  2. دروازه XSD را یک بار اجرا کنید، سپس DevTools را به حالت Offline ببرید (یا Wi-Fi را خاموش کنید). کل دمو — از جمله دروازه طرحواره رسمی — همچنان کار می‌کند: یک service worker پس از نخستین استفاده همه‌چیز را در حافظه نهان نگه می‌دارد.
  3. این صفحه نیز متن‌باز است — منطق دمو یک ماژول واحد بدون وابستگی است که می‌توانید به‌طور کامل بخوانید.

نه اسکریپت تحلیلی وجود دارد، نه سرویس گزارش خطا، نه فونت شخص ثالث و نه نقطه پایانی گزارش CSP — خودِ گزارش‌دهی یک اتصال خروجی می‌بود.

آن را با XSD رسمی ISO 20022 اثبات کنید

گام‌های 1–2 بررسی‌های سریع و دست‌نویس را اجرا می‌کنند. این گام نسخه اصل را اجرا می‌کند: یک محیط اجرای Python (از طریق WebAssembly) که xmlschema را با طرحواره رسمی pain.001.001.09 اجرا می‌کند — همان رده اعتبارسنجی که CLI انجام می‌دهد. موتور حدوداً 13 مگابایتی از همین سایت ارائه و فقط یک بار، هنگام درخواست شما دانلود می‌شود (به‌محض آنکه گام 2 یک XML معتبر تولید کند، دانلود آن بی‌سروصدا آغاز می‌شود).

ابتدا در گام 2 XML تولید کنید — دروازه XSD همان خروجی را اعتبارسنجی می‌کند.

    همه‌چیز در این صفحه در مرورگر شما اجرا می‌شود — هیچ‌چیز بارگذاری، ذخیره یا به جایی ارسال نمی‌شود. این دمو زیرمجموعه‌ای از خط لوله را پیاده‌سازی می‌کند (فیلدهای الزامی، IBAN mod-97، ساختار BIC، قالب‌های مبلغ و تاریخ، جمع‌های کنترلی NbOfTxs/CtrlSum بازمحاسبه‌شده). گام 3 دروازه رسمی XSD را همین‌جا از طریق WebAssembly اجرا می‌کند. زنجیره ابزار نصب‌شده اعتبارسنجی JSON Schema و پنج مجموعه قواعد طرح را نیز بر آن می‌افزاید — برای خط لوله کامل CLI را نصب کنید.

    این دمو چه چیزی نشان می‌دهد — و خط لوله واقعی چه می‌افزاید

    هر دسته نمونه به‌صورت فایل CSV نیز قابل دانلود است تا الگوی خروجی ERP یا صفحه‌گسترده خودتان باشد — ردیف سرستون همان قرارداد است.

    دموی بالا لایه شکست سریع خط لوله Pain001 را پیاده‌سازی می‌کند: بررسی فیلدهای الزامی، ارقام کنترلی IBAN طبق ISO 13616 mod-97، ساختار BIC طبق ISO 9362، قالب‌های مبلغ و تاریخ، و جمع‌های کنترلی (NbOfTxs, CtrlSum) که به‌جای اعتماد، از خود رکوردها بازمحاسبه می‌شوند. منوی «افزودن خطا…» را امتحان کنید — هر سناریو دقیقاً یک نقص واقع‌گرایانه می‌کارد (یک رقم جابه‌جاشده IBAN، یک BIC بدشکل، یک ستون گمشده، مبلغی با ممیز ویرگولی اروپایی، تاریخی ناممکن) و یافته سطح ردیفی را نشان می‌دهد که درگاه بانک در غیر این صورت روزها بعد گزارش می‌کرد.

    زنجیره ابزار نصب‌شده دروازه‌ای بسیار عمیق‌تر اجرا می‌کند: اعتبارسنجی JSON Schema برای هر رکورد با نرمال‌سازی نام‌های جایگزین فیلدها، پنج مجموعه قواعد طرح (SEPA SCT، Instant، SDD Core، B2B، برون‌مرزی) با خروجی --explain قاعده‌به‌قاعده، و اعتبارسنجی نهایی سند تولیدشده با XSD رسمی ISO 20022 پیش از نوشتن حتی یک بایت. ده نسخه pain.001 و pain.008.001.02 پشتیبانی می‌شوند.

    pip install pain001
pain001 -t pain.001.001.09 -d payments.csv -o out/ --scheme sepa-sct --dry-run

    گام 3 در بالا شبیه‌سازی نیست: یک محیط اجرای Python را در WebAssembly راه‌اندازی می‌کند و xmlschema را با طرحواره رسمی pain.001.001.09، که از همین سایت ارائه می‌شود، اجرا می‌کند — همان رده دروازه XSD که CLI اعمال می‌کند. آنچه مختص CLI می‌ماند، بقیه خط لوله است: نرمال‌سازی JSON Schema، پنج مجموعه قواعد طرح با --explain، و ده تعریف پیام دیگر.
